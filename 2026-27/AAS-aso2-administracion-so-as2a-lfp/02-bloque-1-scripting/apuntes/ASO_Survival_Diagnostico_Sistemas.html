Antes de diagnosticar: observa → localiza → comprueba → actúa

Un administrador no debería empezar reiniciando servicios o matando procesos al azar. Primero necesita evidencias: qué ha ocurrido, cuándo, qué proceso o servicio está implicado y si el problema es local, de red o de resolución de nombres.

📜 Logs y journalctl

Un log es un registro de eventos. En Linux puedes encontrar registros tradicionales en /var/log, pero en sistemas con systemd muchos eventos se consultan mediante el journal de systemd-journald.

journalctlMuestra entradas del journal accesibles al usuario.
journalctl -bSolo el arranque actual.
journalctl -b -1Arranque anterior, si está almacenado.
journalctl -u ssh.serviceFiltra por una unidad/servicio.
journalctl -p errErrores y prioridades más graves.
journalctl --since "10 min ago"Filtra por tiempo reciente.
journalctl -fSigue nuevas entradas en tiempo real.
tail -n 50 /var/log/syslogEjemplo de lectura de un log de texto, si la distribución lo usa.
Ojo: no todas las distribuciones crean los mismos ficheros en /var/log. En Ubuntu/Debian puede existir syslog; otras distribuciones dependen más del journal.

⚙️ Buscar procesos

Un proceso es una instancia de un programa en ejecución. Cada proceso tiene un PID. Para diagnosticar, primero identifica el proceso y solo después valora si debe finalizarse.

ps auxFoto de muchos procesos con usuario, CPU, memoria y orden ejecutada.
pgrep -a sshdBusca procesos por nombre y muestra PID + orden.
topVista dinámica del consumo de procesos.
kill PIDEnvía SIGTERM por defecto: pide terminar de forma ordenada.
kill -9 PIDSIGKILL: finalización forzada. Úsalo como último recurso.
systemctl status sshSi es un servicio systemd, revisa estado y últimos mensajes.

🌐 DNS y nslookup

DNS traduce nombres como servidor.empresa.local a direcciones IP. nslookup permite consultar un nombre o una IP y también preguntar a un DNS concreto.

nslookup ejemplo.comPregunta al DNS configurado por defecto.
nslookup ejemplo.com 1.1.1.1Pregunta específicamente al servidor 1.1.1.1.
nslookup -type=MX ejemplo.comConsulta registros MX de correo.
resolvectl statusEn sistemas systemd-resolved, muestra DNS y resolución por interfaz.
Idea clave: si haces ping a una IP pero no a un nombre, sospecha de DNS antes que de la conexión física.

🥾 Arranque: NTLDR no es Windows moderno

NTLDR pertenece al arranque clásico de Windows NT/2000/XP sobre BIOS/MBR y se apoyaba, entre otros elementos, en boot.ini y NTDETECT.COM. Desde Windows Vista/Server 2008 la familia moderna utiliza Windows Boot Manager (BOOTMGR) y la base BCD; con UEFI interviene además la partición EFI.

NTLDR + boot.iniEsquema antiguo: Windows XP/2000/NT.
BOOTMGR + BCDEsquema moderno desde Vista/Server 2008.
bcdeditConsulta/modifica BCD desde Windows con privilegios adecuados.
No trates un error de Windows 11 buscando NTLDR: estarías usando el modelo de arranque de otra generación.

🔌 Redes: diagnosticar por capas

Antes de culpar a Internet, comprueba la configuración local: interfaz, dirección IP, puerta de enlace, ruta y DNS. Después prueba conectividad y, por último, servicios/puertos.

ip addrDirecciones de las interfaces Linux.
ip routeTabla de rutas; busca la ruta default.
ping -c 4 8.8.8.8Prueba conectividad IP (si ICMP no está filtrado).
ss -tulpnSockets TCP/UDP en escucha y procesos, según permisos.
ipconfig /allConfiguración IP completa en Windows.
tracert destinoRuta aproximada en Windows.
