Configuración de red TCP/IP

Configurar, comprobar y resolver nombres en una red TCP/IP, en Windows y en Linux — el último tramo de UD2 antes del examen de RA1+RA2.

Fuente: Fernández Fidalgo, F. — Implantación de sistemas operativos (Síntesis), capítulo 4 — "Operaciones básicas: administración de software base", apartado 4.2.3 "Configuración de red" (pp. 136-142).

01

El modelo TCP/IP: 4 capas

TCP/IP (Transmission Control Protocol / Internet Protocol) es el conjunto de protocolos que hace posible Internet. Se organiza en 4 capas, cada una con una función concreta.

AplicaciónSSH, DNS, SMTP, HTTP — interfaz de usuario
TransporteTCP, UDP, ICMP — comunicación punto a punto
InternetIP, IPSEC, ICMP, IGMP — transmisión lógica de datos
Interfaz de redARP, NDP, L2TP, Ethernet — transmisión física

Es una simplificación del modelo OSI de 7 capas: Aplicación agrupa Aplicación+Presentación+Sesión de OSI, Transporte e Internet se corresponden 1:1 con Transporte y Red de OSI, e Interfaz de red agrupa Enlace de datos+Física.

02

Configurar la IP

En ambos sistemas puedes dejar que un servidor DHCP asigne la IP automáticamente, o fijarla tú a mano (IP estática) junto con máscara de subred, puerta de enlace y DNS.

Windows

GUI: Conexiones de red → clic derecho en el adaptador → Propiedades → Protocolo TCP/IP → Propiedades. Ahí eliges "Obtener una IP automáticamente" (DHCP) o "Usar la siguiente dirección IP" y rellenas IP, máscara, puerta de enlace y DNS.

CLI: para consultar la configuración actual, se usa ipconfig:

ipconfig           · resumen
ipconfig /all      · detalle completo

Linux

La configuración se guarda en un fichero de texto: /etc/network/interfaces o /etc/network/interfaces.d/setup, según la distribución.

Por DHCP (automática):

auto eth0
iface eth0 inet dhcp

Estática (a mano):

auto eth0
iface eth0 inet static
    address 192.168.0.2
    netmask 255.255.255.0
    network 192.168.0.0
    broadcast 192.168.0.255
    gateway 192.168.0.1
Los nombres de interfaz en Linux no son aleatorios: lo (loopback), eth0/eth1 (Ethernet), wlan0 (Wi-Fi), ppp0 (módem), hci0 (Bluetooth).
03

Resolución de nombres

Los recursos de red se reconocen por su nombre (p. ej. servidor1), pero para conectarse hace falta su dirección IP. A eso se le llama resolución de nombres.

Windows

Orden habitual de resolución de un nombre de host:

  1. ¿Es un recurso propio?
  2. Archivo hosts local
  3. Consulta DNS
  4. Resolución de nombres NetBIOS (último recurso)

El archivo hosts está en: C:\Windows\System32\drivers\etc\hosts

Linux

El orden de búsqueda lo define /etc/nsswitch.conf (normalmente hosts: files dns, es decir: primero el archivo, luego DNS).

Si no hay servidor DNS local, se puede resolver a mano en: /etc/hosts

127.0.0.1    localhost
::1          localhost ip6-localhost

El servidor DNS a consultar se indica en /etc/resolv.conf.

Para qué sirve editar hosts a mano: además de resolver nombres sin DNS, sirve para bloquear direcciones maliciosas apuntándolas a 127.0.0.1 (tu propia máquina, donde no hay nada que servir).
04

Comprobar que funciona

Comandos de referencia para verificar la configuración una vez aplicada (de uso estándar en ambos sistemas, no literal del libro):

ComandoSistemaPara qué sirve
ping IP/hostAmbosComprobar si hay conectividad con otro equipo.
ipconfig /allWindowsVer la configuración IP completa de todos los adaptadores.
ip addrLinuxVer direcciones IP asignadas a cada interfaz (sustituye al antiguo ifconfig).
ss -tulpnLinuxVer qué puertos están escuchando y qué proceso los usa (sustituye a netstat).
nslookup / digAmbos / LinuxComprobar manualmente la resolución DNS de un nombre.
05

Para practicar

01

Lee tu configuración actual en Windows

Ejecuta ipconfig /all y localiza: tu IP, máscara de subred, puerta de enlace y los dos servidores DNS. Anótalos.

02

Bloquea un dominio con el archivo hosts

Edita (como administrador) C:\Windows\System32\drivers\etc\hosts y añade una línea que apunte un dominio inventado a 127.0.0.1. Comprueba con ping que resuelve a esa IP.

03

Configura una IP estática en Linux

En una máquina virtual de prueba, edita /etc/network/interfaces.d/setup (o el fichero equivalente de tu distribución) y configura eth0 en modo static con una IP de tu elección en la misma red que el host.

04

Verifica puertos abiertos

Ejecuta ss -tulpn y localiza qué proceso tiene abierto el puerto 22 (SSH) si lo tienes instalado. Compara con ip addr para confirmar en qué interfaz escucha.
