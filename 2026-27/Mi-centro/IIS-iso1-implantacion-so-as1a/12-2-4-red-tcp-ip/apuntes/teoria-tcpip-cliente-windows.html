Red TCP/IP en un cliente Windows 11

Criterio de evaluación: RA2.d

Objetivo: configurar la red TCP/IP de un cliente Windows 11 (IP, máscara, puerta de enlace y DNS) de forma gráfica y por comandos, comprobar que funciona y diagnosticar los errores típicos.

1. Los cuatro datos (igual que en Linux)

Dato Para qué sirve Cómo lo llama Windows
IPIdentifica al equipo. No se puede repetir en la misma red.Dirección IPv4
MáscaraIndica quién es vecino. Windows la muestra en decimal.Máscara de subred (255.255.255.0) o Longitud del prefijo de subred (24)

Resumen rápido: clases de IP, públicas y privadas

Las IPv4 se agrupaban en clases según el primer número. Hoy se usa CIDR (la máscara puede ser cualquiera), pero las clases siguen usándose para hablar de las redes.

Clase Primer número Máscara por defecto Rango privado
A1 – 126/8 · 255.0.0.010.0.0.0 – 10.255.255.255
B128 – 191/16 · 255.255.0.0172.16.0.0 – 172.31.255.255
C192 – 223/24 · 255.255.255.0192.168.0.0 – 192.168.255.255
D224 – 239Multidifusión (multicast): un emisor, varios receptores
E240 – 255Experimental, no se usa
  • IP privada: solo vale dentro de una red local. No circula por Internet y se puede repetir en otras empresas. Para salir a Internet, el router la traduce a su IP pública (NAT).
  • IP pública: única en todo Internet. La asigna el proveedor (ISP). Ejemplo: 8.8.8.8.
  • Direcciones especiales: 127.0.0.1 loopback (el propio equipo; por eso el 127 no está en la clase A) · 169.254.x.x APIPA (sin DHCP) · 0.0.0.0 «cualquier red» (ruta por defecto) · 255.255.255.255 difusión.

Nuestra red 192.168.100.0/24 es privada de clase C.

2. Nuestro escenario

La máquina Windows 11 tiene dos adaptadores en VirtualBox. Windows los llama Ethernet y Ethernet 2 (el nombre puede variar):

Adaptador Nombre en Windows Configuración
1 · NATEthernetAutomática (DHCP). Da Internet. No se toca.
2 · Red interna ferreteriaEthernet 2IP 192.168.100.51 · máscara 255.255.255.0 · sin puerta de enlace · DNS 8.8.8.8 y 8.8.4.4

Equipos de la red interna: Ubuntu Server .10, Windows Server .11, Ubuntu Desktop .50, Windows 11 .51.

La puerta de enlace la da el NAT. En «Ethernet 2» se deja vacía. Si pones una, Windows tendrá dos rutas por defecto y puedes perder Internet. En una oficina real con una sola tarjeta sí pondrías la del router (por ejemplo 192.168.100.1).

2.1 ¿Cómo sé cuál es «Ethernet 2»?

ipconfig /all
  • El adaptador del NAT tiene una IP 10.0.2.x y puerta de enlace 10.0.2.2.
  • El de la red interna, sin configurar, muestra una IP 169.254.x.x.

¿Qué es 169.254.x.x? Es APIPA: una dirección que Windows se asigna a sí mismo cuando el adaptador está en DHCP y no encuentra ningún servidor DHCP. Significa «activo pero sin configurar».

3. Configurar con la interfaz gráfica

Opción A · Configuración de Windows 11

  1. Inicio → Configuración → Red e Internet → Ethernet → elige Ethernet 2.
  2. En Asignación de IP pulsa Editar → Manual → activa IPv4.
  3. Dirección IP: 192.168.100.51 · Máscara de subred: 255.255.255.0 · Puerta de enlace: vacía.
  4. DNS preferido: 8.8.8.8 · DNS alternativo: 8.8.4.4 → Guardar.
  5. En Asignación de servidor DNS, si no se ha cambiado, pulsa Editar y pon los mismos DNS.

Opción B · Panel clásico (más rápido): Win+R → ncpa.cpl → clic derecho en Ethernet 2 → Propiedades → Protocolo de Internet versión 4 (TCP/IPv4) → Propiedades → «Usar la siguiente dirección IP» y «Usar las siguientes direcciones de servidor DNS».

4. Configurar por comandos

Los comandos que cambian la red necesitan una consola como administrador: clic derecho en Inicio → Terminal (Administrador).

4.1 Con netsh (CMD o PowerShell)

netsh interface ipv4 set address name="Ethernet 2" static 192.168.100.51 255.255.255.0
netsh interface ipv4 set dnsservers name="Ethernet 2" static 8.8.8.8 primary
netsh interface ipv4 add dnsservers name="Ethernet 2" 8.8.4.4 index=2
netsh interface ipv4 show config name="Ethernet 2"

Fíjate: después de la máscara no ponemos puerta de enlace. En una red con router sería: ... static 192.168.100.51 255.255.255.0 192.168.100.1. Para volver a DHCP: netsh interface ipv4 set address name="Ethernet 2" dhcp.

4.2 Con PowerShell

Get-NetAdapter                                         # nombres de los adaptadores
New-NetIPAddress -InterfaceAlias "Ethernet 2" -IPAddress 192.168.100.51 -PrefixLength 24
Set-DnsClientServerAddress -InterfaceAlias "Ethernet 2" -ServerAddresses 8.8.8.8,8.8.4.4
Get-NetIPConfiguration -InterfaceAlias "Ethernet 2"

En PowerShell la máscara se escribe como prefijo (24). La puerta de enlace se añadiría con -DefaultGateway; aquí no la ponemos.

5. Permitir el ping entrante

El Firewall de Windows bloquea por defecto las peticiones de ping que llegan de otros equipos. Como la red interna no tiene salida a Internet, Windows la clasifica como «Red no identificada» (pública) y la protege. Resultado: Windows puede hacer ping a Ubuntu, pero Ubuntu no recibe respuesta de Windows.

Para permitirlo (consola de administrador):

netsh advfirewall firewall add rule name="Ping ferreteria" protocol=icmpv4:8,any dir=in action=allow remoteip=192.168.100.0/24

Solo abrimos el ping (ICMP tipo 8) y solo para equipos de la red de la ferretería. No se desactiva el firewall.

7. Errores típicos y cómo resolverlos

Error 1 · IP 169.254.x.x en Ethernet 2. El adaptador sigue en automático (DHCP) y no hay servidor DHCP en la red interna. Solución: configura la IP manualmente.

Error 2 · Se configuró el adaptador equivocado. Pusiste la IP fija en «Ethernet» (NAT). Qué verás: se pierde Internet y Ethernet 2 sigue con 169.254.x.x. Solución: devuelve «Ethernet» a automático (netsh interface ipv4 set address name="Ethernet" dhcp y netsh interface ipv4 set dnsservers name="Ethernet" dhcp) y configura Ethernet 2.

Error 3 · Puerta de enlace en la red interna. Qué verás: route print -4 muestra dos filas 0.0.0.0. Internet funciona mal o no funciona. Solución: borra la puerta de enlace de Ethernet 2 (déjala vacía en la interfaz gráfica, o Remove-NetRoute -InterfaceAlias "Ethernet 2" -DestinationPrefix 0.0.0.0/0).

Error 4 · «La operación solicitada requiere elevación». Ejecutaste netsh o PowerShell sin permisos. Solución: abre Terminal (Administrador).

Error 5 · Nombre del adaptador mal escrito. netsh o PowerShell no encuentran «Ethernet2» (sin espacio) o «ethernet 2». Solución: copia el nombre exacto de Get-NetAdapter y ponlo entre comillas.

Error 6 · New-NetIPAddress dice que la dirección ya existe. Ya había una IP configurada. Solución: quítala antes y repite:

Remove-NetIPAddress -InterfaceAlias "Ethernet 2" -AddressFamily IPv4 -Confirm:$false

Error 7 · Ubuntu no recibe respuesta al hacer ping a Windows. Pero Windows sí llega a Ubuntu. Causa: el firewall de Windows bloquea el ping entrante. Solución: la regla del apartado 5.

Error 8 · Ping a 8.8.8.8 sí, a google.com no. Falla el DNS. Revisa los DNS con ipconfig /all y prueba ipconfig /flushdns.

Error 9 · «Conflicto de dirección IP» / estado «Duplicado». Otra máquina tiene 192.168.100.51. ipconfig /all muestra la IP con (Duplicado). Solución: comprueba con arp -a qué MAC tiene esa IP y corrige la IP de una de las dos máquinas.

Error 10 · Máscara incorrecta. Por ejemplo 255.255.0.0. Puede seguir funcionando entre los equipos de la ferretería, pero la configuración es incorrecta: el equipo cree que tiene 65.534 vecinos. Solución: 255.255.255.0.

Escalera de diagnóstico (Windows):

1. ipconfig /all → ¿IP correcta y no 169.254?No → adaptador, configuración manual
2. ping 192.168.100.10 → ¿llego a mi red?No → IP, máscara, adaptador 2 en VirtualBox
3. ping 8.8.8.8 → ¿salgo a Internet?No → route print -4, adaptador NAT
4. nslookup google.com → ¿resuelvo nombres?No → DNS

Intenta responder antes de abrir cada pregunta para ver la solución.

Solución: APIPA: el adaptador está en DHCP y no ha encontrado servidor DHCP.
2. ¿Qué comando muestra la puerta de enlace en Windows?
Solución: route print -4 (o ipconfig).
3. Escribe el comando netsh para poner 192.168.100.51/24 sin puerta de enlace en «Ethernet 2».
Solución: netsh interface ipv4 set address name="Ethernet 2" static 192.168.100.51 255.255.255.0
4. Desde Ubuntu no hay respuesta al ping a Windows, pero desde Windows sí hay respuesta de Ubuntu. ¿Por qué?
Solución: El firewall de Windows bloquea el ping entrante.
5. route print -4 muestra dos filas 0.0.0.0. ¿Qué error se ha cometido?
Solución: Se ha puesto puerta de enlace en la red interna.

Solución: 10.0.5.3 clase A privada · 172.20.1.1 clase B privada · 8.8.8.8 clase A pública.
