Red TCP/IP en el cliente Ubuntu Desktop

Criterio de evaluación: RA2.d

Situación: el puesto cliente del mostrador de la Ferretería Aragón debe tener siempre la misma IP en la red de la tienda para que el servidor lo encuentre, sin perder la salida a Internet.

Entrega: un PDF en la tarea de Aeducar (ver apartado «Qué entregas»).

Datos

Interfaz Configuración
enp0s3 · Adaptador 1 · NATDHCP (no se toca)
enp0s8 · Adaptador 2 · Red interna ferreteriaIP 192.168.100.50/24 · sin puerta de enlace · DNS 8.8.8.8, 8.8.4.4
Servidor Ubuntu (pruebas)192.168.100.10

Si tu interfaz interna tiene otro nombre (lo ves con ip -br a), úsalo en todos los pasos.

Antes de empezar, guarda cómo está tu red ahora, por si tienes que volver atrás:

mkdir -p ~/copia-red
sudo cp /etc/netplan/*.yaml ~/copia-red/
ip -br a > ~/copia-red/estado-inicial.txt

Usa siempre sudo netplan try: si te quedas sin red y no confirmas, vuelve sola a la configuración anterior. Si ya aplicaste y algo va mal, borra tu archivo (sudo rm /etc/netplan/01-netcfg.yaml), restaura la copia (sudo cp ~/copia-red/*.yaml /etc/netplan/) y ejecuta sudo netplan apply.

Misión 1 · Adaptador 2 en red interna

  1. Con la VM apagada: VirtualBox → Configuración → Red → Adaptador 2 → Habilitar → Conectado a: Red interna → Nombre: ferreteria. El adaptador 1 sigue en NAT.
  2. Arranca y comprueba que aparecen las dos interfaces:
ip -br a
ls -l /etc/netplan/

Misión 2 · Archivo Netplan

sudo nano /etc/netplan/01-netcfg.yaml

Escribe (sangría con espacios, 2 por nivel):

network:
  version: 2
  renderer: NetworkManager
  ethernets:
    enp0s3:
      dhcp4: true
    enp0s8:
      dhcp4: false
      addresses:
        - 192.168.100.50/24
      nameservers:
        addresses: [8.8.8.8, 8.8.4.4]

Guarda (Ctrl+O, Intro) y sal (Ctrl+X). Ajusta permisos:

sudo chmod 600 /etc/netplan/01-netcfg.yaml

Misión 3 · Comprobar y aplicar

sudo netplan generate
sudo netplan try          # pulsa Intro para confirmar
sudo netplan apply

Si sale un error, lee la línea y columna que indica, corrige y repite. Apunta el error y cómo lo resolviste: suma en la nota.

Misión 4 · Verificación

Ejecuta y comprueba que obtienes el resultado correcto:

Comando Debes ver
ip -br aenp0s8 UP 192.168.100.50/24
route -n (o ip route)Una sola ruta por defecto, por enp0s3
resolvectl dns8.8.8.8 8.8.4.4 en enp0s8
ping -c 4 192.168.100.100% packet loss
ping -c 4 8.8.8.80% packet loss
nslookup google.comUna o varias líneas Address:

Si falta algún comando: sudo apt install net-tools dnsutils. Si algo falla, sigue la escalera de diagnóstico de la teoría.

Misión 5 · Persistencia

Reinicia la máquina (sudo reboot) y comprueba con ip -br a que la IP 192.168.100.50/24 sigue puesta.

Misión 6 · Generar el archivo de evidencias

Copia este bloque entero en la terminal y pulsa Intro. Te pedirá tu contraseña una vez. Genera el archivo red_linux_<equipo>.txt en tu carpeta personal:

sudo -v
{
echo "##### CABECERA";  whoami; hostname; date '+%F %T'
echo "##### L1 NETPLAN"; ls -l /etc/netplan/; sudo cat /etc/netplan/01-netcfg.yaml
echo "##### L2 IP";      ip -br a
echo "##### L3 RUTAS";   ip route; route -n
echo "##### L4 DNS";     resolvectl dns
echo "##### L5 PING_LAN"; ping -c 4 192.168.100.10
echo "##### L6 PING_INTERNET"; ping -c 4 8.8.8.8
echo "##### L7 NSLOOKUP"; nslookup google.com
echo "##### L8 ARRANQUE"; uptime -s
echo "##### FIN"
} 2>&1 | tee ~/red_linux_$(hostname).txt

No edites el archivo generado. Si algo ha salido mal, corrige la configuración y vuelve a ejecutar el bloque completo.
