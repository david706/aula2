00MISIÓN · BOOT

Bienvenido a Linux

Antes de escribir un solo comando, tienes que entender qué es lo que te está escuchando.

🖥️ LA TERMINAL

Es la ventana donde escribes. No hace nada por sí sola: solo envía lo que escribes a otro programa y te devuelve la respuesta.

⚙️ LA SHELL

Es el programa que interpreta lo que escribes. La más común en Linux se llama bash. Cuando pulsas Enter, es la shell quien decide qué hacer con tu orden.

📍 EL PROMPT

Es la línea que te dice: "estoy listo, escribe algo". Contiene más información de la que parece.

alumno@iso-lab:~$▍
Léelo así: alumno (quién eres) @ iso-lab (en qué máquina) : ~ (dónde estás) $ (nivel de usuario normal — sería # para root)
⌨️ ATAJOS QUE TE SALVAN

No son comandos: son teclas que la terminal entiende en cualquier momento, incluso a media escritura.

Ctrl + C# cancela lo que se está ejecutando
Ctrl + L# limpia la pantalla (igual que el comando clear)
↑ / ↓# recorren los comandos anteriores
🚨 CUANDO ALGO FALLA

Si ves algo como bash: comnd: command not found, la shell no te está castigando: te está diciendo exactamente qué palabra no reconoce. Casi siempre es una errata. Léelo antes de asustarte.

/ es la raíz de todo. /home/alumno es tu territorio: se abrevia como ~

01MISIÓN · NAVEGACIÓN

No perderte en Linux

Antes de administrar un sistema, tienes que saber dónde estás.

Estás aquí: /home/alumno — dos carpetas por debajo de la raíz
📍 SENSOR DE POSICIÓN
$pwd

Muestra el directorio exacto en el que te encuentras ahora mismo.

👁️ RADAR
$ls
$ls -la

ls muestra lo que contiene el directorio actual. Añadiendo -la ves también los archivos ocultos, los permisos y el propietario de cada uno.

🚶 MOVIMIENTO
$cd Documentos
$cd ..
$cd ~
$cd /
cd carpeta entra · cd .. sube un nivel · cd ~ vuelve a tu carpeta personal · cd / va a la raíz
🧹 LIMPIAR LA PANTALLA
$clear

Borra todo lo que se ve en la terminal. No borra nada del sistema — es solo la pantalla, no la memoria.

🕓 MEMORIA DEL SISTEMA
$history

Muestra todos los comandos que has ejecutado antes, numerados. Puedes repetir cualquiera con ! seguido de su número.

Ejemplo: si history muestra 42 pwd, entonces !42 vuelve a ejecutar ese pwd.
⚡ TRUCO DEL OPERADOR

Pulsa TAB mientras escribes una ruta. Linux completa automáticamente nombres de archivos y carpetas — y si hay varias opciones, pulsándolo dos veces te las muestra todas.

🧠 NO MEMORICES ESTO

Un administrador no recuerda todas las opciones de todos los comandos: sabe encontrarlas. Prueba man ls o ls --help antes de buscar en internet.

02MISIÓN · ARCHIVOS

Manipular el sistema

Ahora que sabes moverte, toca construir y destruir — con cuidado, porque aquí no hay papelera.

Los nodos naranjas son lo que tú creas — el sistema no viene con ellos de fábrica
🏗️ CONSTRUCCIÓN
$mkdir carpeta
$mkdir -p ruta/con/subcarpetas

mkdir crea un directorio. Con -p crea de golpe toda una ruta, aunque las carpetas intermedias no existan todavía.

📄 CREAR ARCHIVOS
$touch nota.txt

Crea un archivo vacío. Si ya existe, no lo borra ni lo vacía: solo actualiza su fecha de modificación.

📋 COPIAR
$cp nota.txt copia.txt
$cp -r carpeta/ destino/

cp copia archivos. Para copiar una carpeta entera necesitas -r (recursivo) — si no, cp se negará y te lo dirá.

🚚 MOVER Y RENOMBRAR
$mv nota.txt evidencias/

Linux no tiene un comando "rename" aparte: mv mueve y renombra a la vez. Si el destino es una carpeta, mueve; si es un nombre nuevo en el mismo sitio, renombra.

🚨 EL COMANDO QUE NO PERDONA

rm borra de verdad — no hay papelera de reciclaje que lo recupere. Antes de pulsar Enter, comprueba con pwd y ls dónde estás y qué vas a borrar. Con rm -r carpeta/ borras la carpeta entera, sin avisos.

🗑️ ELIMINAR
$rm archivo.txt
$rm -r carpeta/

Elimina archivos con rm, y carpetas enteras añadiendo -r.

🧠 NO MEMORICES ESTO

El comodín * sustituye a "cualquier cosa": rm *.txt borra todos los .txt del directorio actual. Pruébalo primero con ls *.txt para ver qué afectaría, antes de usarlo con rm.

03MISIÓN · INVESTIGACIÓN

Encontrar información

En un sistema real no memorizas dónde está algo: aprendes a preguntárselo.

grep 'error' encuentra la aguja sin obligarte a leer el pajar entero
👀 LEER SIN EDITAR
$cat archivo.txt
$less archivo.txt

cat vuelca todo el archivo de golpe — bien para archivos cortos, mal para uno de 10.000 líneas. less lo abre página a página: espacio avanza, b retrocede, /palabra busca dentro, q sale.

✂️ VER SOLO UN TROZO
$head -n 5 archivo.txt
$tail -n 5 archivo.txt

head muestra las primeras líneas, tail las últimas. Útil cuando el archivo es enorme y solo te interesa el principio o el final — como un registro que crece cada segundo.

📝 UN ATAJO PARA TENER ALGO QUE BUSCAR

Para practicar necesitas contenido real. echo "texto" > archivo escribe texto en el archivo (lo sobrescribe si ya existía). echo "texto" >> archivo añade una línea más al final, sin borrar lo anterior. Más abajo verás por qué funciona esto.

🔗 TUBERÍAS — CONECTAR COMANDOS
$ls -la | grep txt
$history | grep cd
$cat sistema.log | grep error | wc -l

El símbolo | (pipe, se lee "tubería") toma la salida de un comando y la convierte en la entrada del siguiente. En vez de guardar resultados a medias, encadenas herramientas pequeñas — así piensan los comandos de Linux entre sí.

Léelo como una cadena de montaje, de izquierda a derecha: cat saca el contenido del archivo → grep se queda solo con las líneas de error → wc -l cuenta cuántas hay.
📤 REDIRECCIÓN — MANDAR LA SALIDA A OTRO SITIO
$comando > salida.txt# sobrescribe salida.txt
$comando >> salida.txt# añade al final, sin borrar
$comando 2> errores.txt# guarda solo los errores
$comando 2> /dev/null# tira los errores a la nada

Por omisión, todo lo que imprime un comando va a la pantalla. Con > lo mandas a un archivo en vez de verlo.

1 es la salida normal (stdout) — es la que usa > por defecto. 2 es la de errores (stderr). /dev/null no es un archivo real: es un agujero negro que borra todo lo que le mandas, útil cuando un error no te importa.
⚡ COMBINÁNDOLO TODO

grep timeout sistema.log 2> /dev/null | wc -l — busca "timeout", descarta cualquier error silenciosamente, y cuenta cuántas líneas coincidieron. Tres ideas pequeñas, una sola línea.

🔍 GREP — BUSCAR DENTRO DE ARCHIVOS
$grep kernel sistema.log
$grep --color error sistema.log

grep muestra solo las líneas que contienen lo que buscas. Con --color resalta la coincidencia dentro de la línea, en vez de solo darte la línea entera.

Ejemplo real: grep 'processor' /proc/cpuinfo | wc -l cuenta cuántos núcleos tiene la máquina — combinando grep con otro comando.
🧭 FIND — BUSCAR ARCHIVOS
$find . -name "*.log"
$find . -maxdepth 1 -type f

find no busca dentro de los archivos, busca los archivos mismos: por nombre, por tipo, por profundidad de carpetas. -maxdepth 1 le dice que no baje a subcarpetas.

Y se combinan: find . -maxdepth 1 -type f | xargs grep -F 'error' — primero find localiza los archivos del directorio actual, luego grep busca dentro de cada uno.
⚡ TRUCO DEL OPERADOR

which comando te dice la ruta exacta del programa que se ejecuta cuando escribes ese nombre. apropos palabra lista comandos relacionados con esa palabra, para cuando sabes lo que quieres hacer pero no el nombre del comando.

🧠 NO MEMORICES ESTO

Ya viste que las tuberías conectan comandos pequeños en vez de depender de uno gigante que lo haga todo. Esa es la filosofía de Unix entera: aprende a combinar find, grep y wc antes que a memorizar opciones sueltas de cada uno.

04MISIÓN · IDENTIDAD

Usuarios y permisos

En Linux, quién eres decide qué puedes tocar. Todo archivo tiene dueño, grupo, y reglas para el resto.

Tres bloques de tres letras: r (leer), w (escribir), x (ejecutar) — para dueño, grupo y el resto del mundo
🪪 QUIÉN ERES
$whoami
$id

whoami dice tu nombre de usuario. id da más detalle: tu UID (número de usuario), tu GID (grupo principal) y todos los grupos a los que perteneces.

🛡️ SUDO — PODER TEMPORAL
$sudo apt update

sudo ejecuta un único comando como root (el superusuario), y te pide tu propia contraseña para confirmarlo. No te convierte en root para siempre: solo presta ese poder para esa línea.

Cuanto más simple sea el comando después de sudo, mejor. No hay deshacer cuando algo sale mal como root.
🔧 CAMBIAR PERMISOS
$chmod +x script.sh
$chmod 755 script.sh

La forma con letras (+x) añade un permiso sin tocar los demás. La forma numérica lo fija todo de golpe: cada dígito es la suma de r=4, w=2, x=1 para usuario, grupo y otros. 755 = rwx para ti, r-x para el resto.

👤 CAMBIAR DUEÑO
$sudo chown usuario:grupo archivo

chown cambia quién es el dueño de un archivo o carpeta. Casi siempre necesita sudo, porque estás tocando algo que no es tuyo.

🚨 SUDO NO PERDONA MÁS QUE RM

¿Recuerdas que rm no tiene papelera? Con sudo rm -r carpeta/ el poder de borrar se extiende a todo el sistema, no solo a tus archivos. Antes de escribir sudo, para y relee el comando completo.

🧠 NO MEMORICES ESTO

No memorices tablas de números — súmalos: r=4, w=2, x=1. Si quieres rwx completo, es 4+2+1=7. Si quieres solo lectura, es 4. chmod 644 es "yo leo y escribo, el resto solo lee".

🎯 MISIÓN 04

  • Ejecutaste el script con ./ delante — sin eso, Linux no sabe que quieres correrlo desde aquí

05MISIÓN · SOFTWARE

Instalar y mantener

Tu sistema no trae todo de fábrica — pero casi todo está a un comando de distancia.

update prepara la lista — install es quien de verdad trae el paquete
🔄 ACTUALIZAR EL ÍNDICE
$sudo apt update

No instala ni actualiza nada todavía: solo refresca la lista de qué versiones existen en los repositorios. Es el paso que casi siempre se olvida y luego da errores raros.

⬆️ ACTUALIZAR PAQUETES
$sudo apt upgrade

Ahora sí: instala las versiones más nuevas de lo que ya tienes. update mira el catálogo, upgrade compra lo que cambió.

📦 INSTALAR Y DESINSTALAR
$sudo apt install tree
$sudo apt remove tree

install trae un paquete nuevo y todo lo que necesita para funcionar. remove lo quita, pero deja su configuración por si vuelves a instalarlo.

Si quieres borrar también la configuración: sudo apt purge tree.
🧩 DPKG — BAJO EL CAPÓ
$dpkg -l | grep tree
$sudo dpkg -i paquete.deb

apt es la capa cómoda; dpkg es la herramienta de más bajo nivel que hay debajo, y la que usas para instalar un .deb que descargaste a mano.

⚡ TRUCO DEL OPERADOR

apt search palabra busca paquetes por nombre o descripción. apt show paquete te da la ficha completa antes de instalar nada.

🧠 NO MEMORICES ESTO

Todo comando que instala, actualiza o borra software necesita sudo — estás modificando el sistema para todos los usuarios, no solo tu carpeta personal.

🎯 MISIÓN 05

06MISIÓN · PROCESOS

Saber qué está funcionando

Todo lo que corre en tu sistema es, en el fondo, un proceso con un número.

Todo proceso cuelga de un padre — hasta llegar a systemd, PID 1, el primero de todos
📋 LISTAR PROCESOS
$ps aux

Muestra una foto de todos los procesos activos: quién los lanzó, cuánta CPU y memoria usan, y su PID (el número que los identifica).

Combínalo con lo que ya sabes: ps aux | grep nginx encuentra solo lo que te interesa.
📊 MONITOR EN VIVO
$top
$htop

top viene instalado de serie y se actualiza sola; htop es la misma idea con colores y con el ratón. Pulsa q para salir de cualquiera de las dos.

🔪 TERMINAR PROCESOS
$kill PID
$kill -9 PID

kill PID le pide al proceso que se cierre de forma ordenada. Con -9 lo fuerzas: no le da tiempo a guardar nada, úsalo solo cuando el proceso no responde a nada más.

⚙️ SERVICIOS DEL SISTEMA
$systemctl status nginx
$sudo systemctl restart nginx

Un servicio es un proceso que arranca solo con el sistema y se supervisa a sí mismo. status te dice si está vivo; restart lo reinicia sin tener que buscarle el PID a mano.

⚡ TRUCO DEL OPERADOR

pgrep nombre te da el PID sin pasar por ps | grep. pkill nombre lo mata directamente por nombre — más rápido, pero más fácil de equivocarse de proceso.

🧠 NO MEMORICES ESTO

Antes de matar un proceso a lo bruto, prueba systemctl restart si es un servicio. Reinicia limpio, sin dejar nada a medias.

07MISIÓN · ALMACENAMIENTO

Discos y espacio

Antes de instalar algo más, comprueba si de verdad tienes sitio.

df mide el disco entero — du mide lo que ocupan tus archivos dentro de él
🧱 VER LOS DISCOS
$lsblk

Lista los discos y particiones conectados al sistema, en forma de árbol, con su tamaño y dónde está montada cada una.

📏 ESPACIO LIBRE
$df -h

df (disk free) muestra cuánto espacio queda por partición. La -h es la misma de siempre: números legibles (GB, MB) en vez de bloques.

📂 QUÉ OCUPA ESPACIO
$du -sh carpeta/
$du -sh * | sort -rh | head

du (disk usage) mide carpetas y archivos concretos. La segunda línea es tu mejor amiga cuando el disco se llena: ordena de mayor a menor y te dice exactamente quién es el culpable.

🔌 MONTAR UNIDADES
$mount /dev/sdb1 /mnt/usb

Un disco conectado no está disponible hasta que lo montas en una carpeta. umount /mnt/usb lo desconecta de forma segura antes de retirarlo físicamente.

🚨 NUNCA DESCONECTES SIN UMOUNT

Sacar un USB sin umount antes es como cerrar un libro a media frase: puede que la última escritura no se haya guardado del todo. Siempre umount primero.

🧠 NO MEMORICES ESTO

df = espacio del disco entero. du = espacio de una carpeta concreta. Si alguna vez no cuadran, casi siempre es un archivo borrado que un proceso todavía tiene abierto.

08MISIÓN · RED

Saber si "hay red" y por qué

Cuando algo "no tiene internet", casi siempre es uno de cuatro puntos en una cadena.

ip a comprueba el primer tramo · ip route el segundo · ping el resto de la cadena
🌐 TU DIRECCIÓN
$ip a

Muestra tus interfaces de red y la IP asignada a cada una. Si aquí no ves una IP razonable, el problema está en tu propio equipo — no hace falta mirar más lejos todavía.

🗺️ LA RUTA DE SALIDA
$ip route

Muestra por dónde sale tu tráfico: la puerta de enlace (gateway) que conecta tu red local con el resto de internet.

📶 ¿HAY RED?
$ping -c 4 8.8.8.8

Envía 4 paquetes y espera respuesta. Con -c 4 se detiene solo; sin ese número, sigue para siempre hasta que pulses Ctrl+C.

Si ping 8.8.8.8 funciona pero ping google.com no, el problema no es la red: es la resolución de nombres (DNS).
🔌 QUÉ ESTÁ ESCUCHANDO
$ss -tulpn

Lista los puertos abiertos en tu máquina y qué proceso los está usando — el reemplazo moderno de netstat.

🧭 RESOLUCIÓN DE NOMBRES
$resolvectl status

Muestra qué servidor DNS estás usando para traducir nombres (google.com) a direcciones IP. Si el ping por IP funciona pero por nombre no, empieza a mirar aquí.

🧠 NO MEMORICES ESTO

Diagnostica en orden, de dentro hacia fuera: ip a (¿tengo IP?) → ip route (¿tengo salida?) → ping IP (¿llega el tráfico?) → ping dominio (¿funciona el DNS?).

🎯 MISIÓN 08

Sigue la cadena de diagnóstico completa, en orden:

$ip a
$ip route
$ping -c 3 8.8.8.8
$ping -c 3 google.com
  • Anotaste tu propia IP local
  • Confirmaste que el problema (si lo hay) es de red o de DNS, no los dos a ciegas

09MISIÓN · DIAGNÓSTICO

Resolver problemas

Un sistema roto casi siempre deja pistas. Tu trabajo es saber dónde mirar, no adivinar.

journalctl es un cat gigante con marca de tiempo — grep sigue funcionando exactamente igual dentro de él
📜 EL DIARIO DEL SISTEMA
$journalctl -xe
$journalctl -u nginx

journalctl es el registro central del sistema. -xe salta directo a los últimos mensajes con más contexto; -u servicio filtra por uno solo.

⏱️ EN VIVO
$journalctl -f

Igual que tail -f del nivel 03, pero para el diario del sistema entero: se queda esperando y muestra cada línea nueva según va llegando.

🗂️ LOGS CLÁSICOS
$sudo tail -n 50 /var/log/syslog

No todo pasa por journalctl: muchos programas siguen escribiendo archivos de texto plano en /var/log/, que se leen con las herramientas que ya conoces.

🔁 REINICIAR UN SERVICIO ROTO
$sudo systemctl restart nginx
$systemctl status nginx

Reinicias, y vuelves a comprobar el estado — nunca das un problema por resuelto sin confirmarlo.

⚡ TRUCO DEL OPERADOR

journalctl --since "10 min ago" acota la búsqueda a lo reciente, en vez de bucear en semanas de historial.

🧠 NO MEMORICES ESTO

El método importa más que el comando exacto: reproduce el problema → mira el log justo en ese momento → aísla la línea con grep → actúa. Ese orden funciona incluso el día que no recuerdes ningún comando.

🎯 MISIÓN 09

Simula una guardia real: un servicio que falló hace unos minutos.
