La idea que une toda la unidad: un sistema operativo es un edificio. Los usuarios son las personas, los grupos son los departamentos, los permisos son las llaves de cada sala y los servicios son el personal de mantenimiento que trabaja aunque no haya nadie en recepción.

1. Usuarios y grupos

10 min

Un usuario es una identidad con un número (UID en Linux, SID en Windows). Lo que de verdad importa al sistema es ese número, no el nombre. Un grupo junta usuarios para dar permisos una sola vez en lugar de uno por uno.

Regla de oro: los permisos se dan a grupos, no a personas. Si mañana entra alguien nuevo en almacén, lo metes en el grupo y ya tiene todo lo que necesita.

Linux (srv-ubuntu)

# crear los departamentos
sudo groupadd contabilidad
sudo groupadd almacen
# usuario con carpeta, shell y grupo
sudo useradd -m -s /bin/bash \
  -g almacen -G becarios luis
sudo passwd luis
# añadir grupo SIN quitar los otros
sudo usermod -aG contabilidad luis
# obligar a cambiarla al entrar
sudo chage -d 0 luis
# comprobar
id luis
sudo chage -l luis

Windows (srv-win / pc-win)

REM cmd como administrador
net localgroup almacen /add
net user luis P4ss-temp /add ^
  /logonpasswordchg:yes
net localgroup almacen luis /add
REM comprobar
net user luis
# PowerShell
$p = Read-Host -AsSecureString
New-LocalUser luis -Password $p
Add-LocalGroupMember almacen -Member luis
Get-LocalGroupMember almacen
Errores típicos: olvidar la -a en usermod -aG (borra los grupos que ya tenía), olvidar -m (el usuario se queda sin carpeta personal) y dar por hecho que la contraseña caduca sin mirarlo con chage -l o net user.

New-LocalUser no tiene una opción directa para «cambiar contraseña en el próximo inicio». Por eso, para ese caso concreto, la forma más corta en Windows es net user … /logonpasswordchg:yes.

2. Permisos

10 min

Linux: tres tríos y tres letras

Cada archivo tiene un dueño, un grupo y el resto. A cada uno se le dan tres letras: r (leer, 4), w (escribir, 2) y x (ejecutar o entrar en el directorio, 1).

drwxrws---  2 root almacen  4096  /srv/almacen
 └┬┘└┬┘└┬┘
 dueño grupo otros     → 770 + bit SGID (la s) = 2770
ComandoPara quéEjemplo
chownCambiar dueño y gruposudo chown root:almacen /srv/almacen
chmodCambiar las letrassudo chmod 2770 /srv/almacen
setfaclDar permiso a alguien que no es ni dueño ni gruposudo setfacl -m g:direccion:rx /srv/almacen
Ojo con los directorios: para «leer y escribir» en una carpeta hace falta también la x. Sin x no se puede entrar, aunque tengas rw. Por eso en una carpeta de grupo se pone rwx (7), no rw- (6).
En Linux solo se aplica un trío: si eres el dueño, el de dueño; si no, el de grupo si perteneces; si no, el de otros. No se suman.

Windows: NTFS y la herencia

En NTFS cada carpeta tiene una lista de entradas (ACL). Los permisos de todos tus grupos se suman, excepto un Denegar, que siempre gana.

REM lectura y escritura (Modificar) al grupo almacen, heredando a subcarpetas y archivos
icacls C:\Datos\Almacen /grant almacen:(OI)(CI)M
REM cortar la herencia copiando lo que había
icacls C:\Datos\Almacen /inheritance:d
REM ver el resultado
icacls C:\Datos\Almacen
# Lo mismo con PowerShell
$acl  = Get-Acl C:\Datos\Almacen
$regla = New-Object System.Security.AccessControl.FileSystemAccessRule(
  "almacen","Modify","ContainerInherit,ObjectInherit","None","Allow")
$acl.AddAccessRule($regla)
Set-Acl C:\Datos\Almacen $acl
(Get-Acl C:\Datos\Almacen).Access | ft IdentityReference,FileSystemRights
LinuxWindows NTFS
¿Se suman los permisos?No: se aplica un tríoSí, salvo Denegar
HerenciaNo (salvo SGID para el grupo y ACL por defecto)Sí, de la carpeta padre

chmod 777 o «Todos: Control total» no son una solución: son abrir la puerta del edificio a cualquiera. Se da el mínimo necesario.

3. Servicios

10 min

Un servicio es un programa que corre en segundo plano sin que nadie inicie sesión: SSH, DNS, la cola de impresión… Siempre hay que distinguir dos preguntas:

¿Está funcionando AHORA?

Linux: start / stop → is-active
Windows: Start-Service → estado Running

¿Arrancará al REINICIAR?

Linux: enable / disable → is-enabled
Windows: tipo de inicio Automatic

Linux

systemctl status ssh
systemctl is-active ssh
systemctl is-enabled ssh
sudo systemctl enable --now ssh
# qué ha pasado (registro)
journalctl -u ssh -n 20
journalctl -u ssh --since today

Windows

Get-Service Spooler
Get-Service | ? Status -eq Running
Set-Service Spooler -StartupType Automatic
Start-Service Spooler
sc.exe query Spooler
sc.exe qc Spooler
sc.exe config Spooler start= auto
En sc.exe config el espacio va después del igual: start= auto. Sin ese espacio, el comando falla. Y en PowerShell hay que escribir sc.exe, porque sc a secas es otro comando.
Un cambio de servicio no está comprobado hasta que reinicias la máquina y vuelves a mirar el estado.

5. Cómo se documenta una tarea de configuración

10 min

Todo lo que entregues en la UD2 debe poder repetirlo otra persona sin preguntarte nada. Cada tarea lleva:

ElementoQué poner
ObjetivoQué se quería conseguir, en una frase.
MáquinaDónde se hizo: srv-ubuntu, pc-ubuntu, srv-win o pc-win.
ComandosExactos, en orden, tal como se teclearon.
Salida realCopia o captura de lo que devolvió el sistema, no lo que «debería» salir.
VerificaciónLa prueba de que funciona: con otro usuario, desde otra máquina o tras reiniciar.
IncidenciasQué falló, por qué y cómo se resolvió. Si no falló nada, se escribe «Sin incidencias».

Ejemplo de incidencias bien documentadas

Qué pasóCausaCómo se resolvió
net user becario1 1234 /add /logonpasswordchg:yes devolvió «La contraseña no cumple los requisitos de la directiva de contraseñas».La política de srv-win exige longitud mínima y complejidad.Se repitió con una contraseña temporal que cumple la política. Comprobado con net accounts.
sudo -u pedro touch /srv/almacen/prueba.txt devolvió Permission denied.Se había puesto chmod 660: sin x en el grupo no se puede entrar en el directorio.sudo chmod 2770 /srv/almacen y se repitió la prueba como pedro: el archivo se crea.
Tras reiniciar srv-ubuntu, ssh estaba inactive.Se había hecho start pero no enable.sudo systemctl enable --now ssh, nuevo reinicio y systemctl is-enabled ssh → enabled.
Una buena incidencia tiene tres partes: el mensaje de error real (copiado, no resumido), la causa y el comando con el que se arregló, más la comprobación de que ya funciona. «Me dio un error y lo arreglé» no vale.

Modelo completo de una tarea documentada

Objetivo: que el grupo almacen pueda leer y escribir en /srv/almacen y nadie más pueda entrar.

Máquina: srv-ubuntu.

Comandos:

sudo groupadd almacen
sudo useradd -m -s /bin/bash -G almacen pedro
sudo mkdir -p /srv/almacen
sudo chown root:almacen /srv/almacen
sudo chmod 2770 /srv/almacen

Salida real:

$ ls -ld /srv/almacen
drwxrws--- 2 root almacen 4096 nov 25 10:14 /srv/almacen

Verificación:

$ sudo -u pedro touch /srv/almacen/prueba.txt
$ ls -l /srv/almacen
-rw-r--r-- 1 pedro almacen 0 nov 25 10:16 prueba.txt
$ sudo -u luis ls /srv/almacen
ls: no se puede abrir el directorio '/srv/almacen': Permiso denegado

Incidencias: el primer intento con chmod 660 dio «Permiso denegado» a pedro al crear el archivo, porque el directorio no tenía x para el grupo. Se corrigió con chmod 2770 y se repitió la verificación con resultado correcto.

Nunca escribas contraseñas reales en el documento. Pon ******** o «contraseña temporal entregada al usuario».
Los dos fallos que más se repiten: entregar comandos sin salida (no demuestra nada) y no comprobar tras reiniciar (un servicio con start pero sin enable parece bien hasta que se apaga la máquina).
Entregas pendientes de la UD2: revisa en Aeducar que tienes subidas las de usuarios, grupos y permisos con este formato antes del plazo.

6. Repaso UD1 (RA1): teoría para el examen

30 min

La UD1 es «entender la máquina»: qué hace un sistema operativo, cómo arranca, cómo se reparte el disco y cómo se organizan los archivos. Aquí tienes lo esencial de cada tema.

6.1 Arquitectura del sistema operativo

El sistema operativo es el programa que hace de intermediario entre el hardware y los programas del usuario. Sus funciones son:

FunciónQué haceEjemplo que ya has visto
ProcesosDecide qué programa usa la CPU y cuánto tiempo (planificación), y crea y termina procesos.ps, top, kill, Administrador de tareas
MemoriaReparte la RAM entre procesos, los aísla y usa el disco cuando falta RAM (memoria virtual).swap en Linux, pagefile.sys en Windows
ArchivosOrganiza los datos del disco en archivos y carpetas, y controla quién accede a ellos.ext4, NTFS, permisos
Entrada/salidaHabla con los dispositivos (disco, teclado, red, impresora) a través de los controladores (drivers)./dev en Linux, Administrador de dispositivos
Seguridad e interfazUsuarios, contraseñas y permisos, y la forma de comunicarse con el usuario (terminal o escritorio gráfico).Toda la UD2

El núcleo (kernel) es la parte del sistema que tiene control total del hardware. Hay tres diseños:

TipoCómo esVentaja / inconvenienteEjemplos
MonolíticoTodo (procesos, memoria, archivos, drivers) corre dentro del núcleo.Muy rápido. Un fallo en un driver puede tumbar todo el sistema.Linux (con módulos que se cargan y descargan)
MicronúcleoEl núcleo hace lo mínimo; el resto son servicios fuera del núcleo.Muy estable: si falla un servicio, se reinicia solo ese. Más lento.Minix, QNX
HíbridoBase de micronúcleo, pero con muchos servicios metidos dentro del núcleo por rendimiento.Equilibrio entre los dos.Windows (NT), macOS
Analogía: el monolítico es un restaurante donde el chef lo hace todo (rápido, pero si se pone enfermo cierra). El micronúcleo es uno donde cada tarea tiene su encargado (si falla uno, se sustituye). El híbrido es el chef con algunos ayudantes de confianza en la cocina.

6.3 Arranque

Al encender: el firmware comprueba el hardware (POST) → busca el gestor de arranque → este carga el núcleo → el núcleo arranca el primer proceso (systemd en Linux) y los servicios.

BIOS (Legacy)UEFI
ÉpocaAntigua (desde los 80)Actual
Tabla de particionesMBRGPT
Dónde busca el arranqueEn el primer sector del discoEn una partición propia, la ESP (FAT32, montada en /boot/efi)
Arranque seguroNoSecure Boot: solo arranca software firmado
  • GRUB: gestor de arranque de Linux. Muestra el menú para elegir sistema o núcleo. Se configura en /etc/default/grub y se aplica con sudo update-grub.
  • Windows Boot Manager: el de Windows. Se consulta y modifica con bcdedit.
  • Arranque dual: dos sistemas en el mismo equipo. Se instala primero Windows y después Linux, porque Windows no reconoce a Linux y sobrescribe el gestor de arranque; GRUB sí detecta a Windows y lo añade a su menú.

6.4 Particionado

Una partición es un trozo del disco que el sistema trata como si fuera un disco independiente.

MBRGPT
Tamaño máximo de disco2 TiBPrácticamente ilimitado
Número de particiones4 primarias, o 3 primarias + 1 extendida que contiene lógicas128 en Windows, sin primarias ni extendidas
SeguridadUna sola copia de la tabla: si se daña, se pierde todoCopia de la tabla al final del disco y comprobación de errores (CRC)
FirmwareBIOSUEFI

Esquema típico de Linux:

  • / (raíz): el sistema.
  • swap: memoria de intercambio; el sistema la usa cuando se llena la RAM (y para hibernar).
  • /home separada: tus datos van aparte. Si reinstalas o cambias de distribución, formateas / y conservas /home.
  • /boot/efi: la partición ESP, solo en equipos UEFI.
lsblk          # discos y particiones en árbol
sudo fdisk -l  # tabla de particiones (dice si es gpt o dos/MBR)
df -h          # espacio usado de lo que está montado

En Windows: diskmgmt.msc (Administración de discos) o diskpart → list disk (un asterisco en la columna GPT indica que el disco es GPT).

6.5 Sistemas de archivos

El sistema de archivos es la forma de organizar los datos dentro de una partición. Sin él, la partición es espacio en blanco.

ext4NTFSFAT32exFAT
SistemaLinuxWindowsTodosTodos (actuales)
Archivo máximo16 TiBEnorme (sin límite práctico)4 GiBSin límite práctico
PermisosSí (rwx)Sí (ACL)NoNo
Diario (journaling)SíSíNoNo
Uso típicoDisco de LinuxDisco de WindowsUSB antiguos, partición ESPUSB y tarjetas SD grandes
Journaling (diario): antes de escribir, el sistema apunta lo que va a hacer. Si se va la luz a mitad, al arrancar repasa el diario y deja el disco coherente. Por eso ext4 y NTFS se recuperan mejor de un apagón que FAT32.
Pregunta típica: «no puedo copiar una ISO de 5 GB a mi USB». El USB está en FAT32 (máximo 4 GiB por archivo). Solución: formatearlo en exFAT o NTFS.

6.6 Árbol de directorios de Linux

En Linux hay un solo árbol que empieza en / (la raíz). Los discos y USB no tienen letra: se «montan» en una carpeta del árbol. Esta organización sigue el estándar FHS y es la misma en Ubuntu, Vitalinux o Fedora.

/
├── bin    programas básicos (ls, cp…); hoy es un enlace a /usr/bin
├── boot   núcleo y GRUB
├── dev    dispositivos como archivos (/dev/sda = primer disco)
├── etc    configuración del sistema (passwd, hosts, netplan…)
├── home   carpetas personales (/home/luis)
├── media  USB y CD montados automáticamente
├── mnt    montajes manuales temporales
├── opt    programas de terceros
├── proc   información de procesos y del núcleo (no está en disco)
├── root   carpeta personal del administrador root
├── tmp    temporales, se borran al reiniciar
├── usr    programas y bibliotecas instalados
└── var    datos que cambian: registros (/var/log), colas, cachés
Regla para recordarlo: configuración en /etc, registros en /var/log, datos del usuario en /home, programas en /usr. Y /root no es lo mismo que /: es solo la carpeta de casa del usuario root.

6.9 Instalación y máquinas virtuales

TipoQué esCuándo
LimpiaSe formatea y se instala desde cero.Equipo nuevo o sistema muy dañado. Es la más estable.
ActualizaciónSe instala la versión nueva encima, conservando programas y datos.Pasar de Windows 10 a 11, o de una versión de Ubuntu a la siguiente.
DesatendidaLas respuestas del instalador van en un archivo y nadie tiene que estar delante.Muchos equipos iguales (autounattend.xml en Windows, autoinstall en Ubuntu).

Requisitos mínimos: antes de instalar se comprueban CPU, RAM, disco y firmware. Ejemplo: Windows 11 pide CPU de 64 bits compatible, 4 GB de RAM, 64 GB de disco, UEFI con Secure Boot y TPM 2.0.

Virtualización: un hipervisor permite ejecutar varias máquinas virtuales en un mismo equipo.

Tipo 1 (nativo, bare metal)

Se instala directamente sobre el hardware, sin sistema debajo. Más rendimiento. Para servidores.

VMware ESXi, Hyper-V, Proxmox (KVM)

Tipo 2 (alojado)

Es un programa que se instala encima de tu sistema operativo. Más cómodo para aprender y probar.

VirtualBox, VMware Workstation

En VirtualBox has usado: instantáneas (volver a un estado anterior), las Guest Additions (mejor pantalla, portapapeles compartido) y los modos de red NAT (salir a Internet) y red interna (que las VM se vean entre ellas).

6.10 Vitalinux

Vitalinux es la distribución Linux del Gobierno de Aragón para los centros educativos. Vitalinux 3 está basada en Xubuntu 22.04 (Ubuntu con escritorio XFCE, ligero), así que casi todo lo de Ubuntu vale igual: apt, el árbol de directorios, systemctl… Los equipos se gestionan de forma centralizada desde el centro.

La filosofía del código abierto: el código se puede ver, estudiar, mejorar y compartir. Para un centro educativo supone no pagar licencias, poder adaptarlo y no depender de un solo fabricante.
