Procesos y servicios

Un proceso es un programa en ejecución en un momento dado; un servicio (o demonio en Linux) es un programa pensado para funcionar siempre en segundo plano, sin interfaz, arrancando normalmente con el sistema — un servidor web, el antivirus, el servicio de impresión. Hoy vemos cómo verlos, pararlos y arrancarlos en los dos sistemas.

Fuente de los comandos de procesos: Fernández Fidalgo, F. — Implantación de sistemas operativos (Síntesis), cap. 5, apdo. 5.4.4–5.4.5 (pp. 176-180). Los comandos de servicios (services.msc, systemctl, journalctl) son conocimiento estándar de referencia, no aparecen literalmente en ese capítulo del libro.

01

Procesos: verlos y terminarlos

En ambos sistemas puedes hacerlo desde una aplicación gráfica o desde la terminal. La CLI es la que de verdad necesitarás en un servidor, que normalmente no tiene escritorio.

Windows

GUI: Administrador de tareas (Ctrl+Alt+Supr o taskmgr).

CLI — tasklist lista procesos, taskkill los mata:

tasklist
taskkill /PID 1234
taskkill /IM notepad.exe

También existe wmic process (más potente, pero en desuso desde Windows 10 en favor de PowerShell/CIM):

wmic process list brief
wmic process where name="notepad.exe" delete

Linux

top (o htop, más cómodo) muestra los procesos en vivo, ordenados por uso de CPU. ps da una foto fija:

ps aux
ps -ef

Para terminarlos — kill por PID, pkill/killall por nombre:

kill PID
kill -9 PID        · terminación forzosa
pkill nombre
killall nombre

renice N PID cambia la prioridad de un proceso (-20 = máxima, 20 = mínima).

02

Servicios: qué son y cómo se gestionan

Un servicio no "se ejecuta y ya está": tiene un estado (iniciado, detenido, pausado) y una configuración de arranque (automático, manual, deshabilitado). Gestionarlo es decidir cuándo arranca y poder pararlo sin apagar el equipo entero.

Windows — services.msc

Se abre con ⊞ Win + R → services.msc. Lista todos los servicios con su estado y tipo de inicio; doble clic en uno para cambiarlo.

Por línea de comandos, el comando es sc (Service Control):

sc query nombre_servicio
sc start nombre_servicio
sc stop nombre_servicio
sc config nombre_servicio start= auto

También puedes usar PowerShell, más moderno:

Get-Service
Start-Service nombre
Stop-Service nombre

Linux — systemctl

La mayoría de distribuciones actuales (incluida Ubuntu) usan systemd como gestor de servicios. El comando es systemctl:

systemctl status nombre
systemctl start nombre
systemctl stop nombre
systemctl restart nombre
systemctl enable nombre   · arranca con el sistema
systemctl disable nombre

Para ver los registros (logs) de un servicio gestionado por systemd, se usa journalctl:

journalctl -u nombre
journalctl -u nombre -f   · en vivo, como tail -f
Relación con lo que ya viste en UD2: el libro trata el registro de eventos del sistema en general (Visor de eventos en Windows, /var/log en Linux) — journalctl es la versión moderna de eso mismo pero específica de servicios systemd, y sustituye en buena parte a mirar archivos sueltos en /var/log.
03

Para practicar

01

Mata un proceso de dos formas en Windows

Abre el Bloc de notas. Localiza su PID con tasklist | find "notepad" y mátalo con taskkill /PID. Repite el ejercicio abriendo otra instancia y usando taskkill /IM notepad.exe directamente.

02

Cambia el arranque de un servicio

Con services.msc, localiza el servicio "Fax" o "Impresora en cola" y cambia su tipo de inicio a Manual. Verifícalo desde cmd con sc qc nombre_servicio.

03

Gestiona un servicio con systemctl

Instala y arranca un servicio sencillo, por ejemplo sudo apt install apache2. Comprueba su estado con systemctl status apache2, detenlo, vuelve a arrancarlo y comprueba con systemctl is-enabled apache2 si arrancará solo al reiniciar.

04

Revisa los logs con journalctl

Con el servicio del ejercicio anterior, párate y vuelve a arrancarlo mientras tienes abierto journalctl -u apache2 -f en otra terminal. Observa qué líneas aparecen en cada acción.
