1 · EL MAPA

El mapa de las distribuciones

Linux es el núcleo; una distribución añade el gestor de paquetes, los repositorios y las decisiones de diseño. Casi todas descienden de unas pocas familias, y el gestor de paquetes es lo que define la familia.

2 · CONCEPTOS

Anatomía de un gestor de paquetes

Da igual la distro: todos hacen lo mismo con otro nombre.

Las piezas

  • Paquete: archivo comprimido con programa + metadatos (versión, dependencias, scripts de instalación).
  • Repositorio: servidor (o espejo) con muchos paquetes y un índice.
  • Índice / metadatos: lista local de qué hay disponible. Si no se refresca, el gestor trabaja con información vieja.
  • Dependencias: lo que el paquete necesita; el gestor lo resuelve y lo instala solo.
  • Firma GPG: garantiza que el paquete viene de quien dice y no ha sido alterado.
  • Base de datos local: qué hay instalado y qué archivos pertenece a cada paquete.

Dos niveles

FamiliaAlto nivel (repos, dependencias)Bajo nivel (un archivo local)
Debianaptdpkg
Red Hatdnfrpm
Archpacmanpacman -U / makepkg

El alto nivel descarga y resuelve dependencias; el bajo nivel solo instala o consulta el archivo que le des. Por eso dpkg -i x.deb falla si faltan dependencias y apt install ./x.deb no.

Los tres hacen las mismas cinco cosas: refrescar índice · actualizar · instalar · quitar · consultar. Si sabes cuál es cuál, cambiar de distro es solo cambiar de vocabulario.

4 · FEDORA

Fedora: dnf y rpm Red Hat

sudo dnf check-update                # qué hay por actualizar (refresca metadatos solo)
sudo dnf upgrade                    # actualiza todo lo instalado   (alias: dnf update)
sudo dnf install vim                # instalar
sudo dnf remove vim                 # quitar
sudo dnf autoremove                 # dependencias huérfanas
dnf search editor ; dnf info vim    # buscar / ficha del paquete
dnf list --installed                # inventario  (equivale a: rpm -qa)
dnf provides /usr/sbin/sshd         # qué paquete aporta ese archivo (aunque no esté instalado)
dnf history                         # historial de transacciones
sudo dnf history undo 12            # deshacer la transacción nº 12
sudo dnf install ./paquete.rpm      # rpm local con resolución de dependencias

# Bajo nivel: rpm (consulta de lo instalado)
rpm -qa | wc -l                     # cuántos paquetes hay
rpm -qi openssh-server              # información
rpm -ql openssh-server              # archivos que instala  (≈ dpkg -L)
rpm -qf /usr/sbin/sshd              # a qué paquete pertenece un archivo  (≈ dpkg -S)
rpm -qc openssh-server              # solo sus archivos de configuración
Ventaja sobre apt: dnf history undo deshace una transacción completa. Con apt hay que reconstruir a mano qué se instaló (/var/log/apt/history.log).

Desde Fedora 41 el comando dnf es DNF 5 (reescrito en C++, mucho más rápido). Los comandos habituales no cambian; sí algunos plugins.

5 · FEDORA

Fedora: repositorios y actualizaciones automáticas

Repositorios

ls /etc/yum.repos.d/                # un .repo por repositorio
dnf repolist                        # repos activos
sudo dnf config-manager setopt updates-testing.enabled=1   # DNF5: activar/desactivar
cat /etc/yum.repos.d/fedora.repo
[fedora]
name=Fedora $releasever - $basearch
metalink=https://mirrors.fedoraproject.org/metalink?...
enabled=1
gpgcheck=1                          # verificar la firma de cada paquete
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-fedora-$releasever-$basearch
  • RPM Fusion: repo de terceros muy usado (códecs, drivers privativos).
  • COPR: repos de usuarios, equivalente a los PPA de Ubuntu; mismo criterio de confianza.

Actualizaciones automáticas

sudo dnf install dnf-automatic
# Fedora 41+ (DNF 5) el paquete es dnf5-plugin-automatic
sudo nano /etc/dnf/automatic.conf
[commands]
upgrade_type = security            # solo seguridad (o: default = todo)
apply_updates = yes                # yes = instalar; no = solo descargar/avisar
[emitters]
emit_via = stdio                   # o email / motd
sudo systemctl enable --now dnf-automatic.timer
systemctl list-timers | grep -i automatic   # comprobar que está programado

El nombre exacto del timer cambia según versión (dnf-automatic.timer, dnf-automatic-install.timer o dnf5-automatic.timer). Se localiza con rpm -ql <paquete> | grep timer.

Fíjate en la analogía con Ubuntu: unattended-upgrades + 50unattended-upgrades ↔ dnf-automatic + automatic.conf. Misma idea: qué instalar (solo seguridad), cuándo (timer) y cómo avisar.
6 · ARCH LINUX

Arch Linux: pacman Arch

pacman usa letras mayúsculas para la operación (-S sync/repos, -Q query/instalado, -R remove, -U upgrade desde archivo) y minúsculas para modificarla.

sudo pacman -Syu                    # sincronizar índice (-y) Y actualizar todo (-u): LA forma de actualizar
sudo pacman -S vim                  # instalar
sudo pacman -S --needed vim         # instalar solo si no está
sudo pacman -R vim                  # quitar el paquete
sudo pacman -Rns vim                # quitar + dependencias huérfanas (-s) + configuración (-n)  ≈ apt purge + autoremove
pacman -Ss editor                   # buscar en repos
pacman -Si vim ; pacman -Qi vim     # ficha en repo / ficha del instalado
pacman -Q | wc -l                   # inventario: cuántos paquetes hay
pacman -Qe                          # solo los instalados explícitamente por ti
pacman -Ql openssh                  # archivos de un paquete   (≈ dpkg -L)
pacman -Qo /usr/bin/ssh             # a qué paquete pertenece un archivo (≈ dpkg -S)
pacman -Qdtq                        # huérfanos
sudo pacman -U ./paquete.pkg.tar.zst   # paquete local
sudo pacman -Sc                     # limpiar caché de paquetes viejos
  • Configuración: /etc/pacman.conf (repos core, extra, multilib, SigLevel) y /etc/pacman.d/mirrorlist (espejos).
  • Log: /var/log/pacman.log. Base de datos local: /var/lib/pacman/.
7 · ARCH LINUX

Arch Linux: AUR y la regla de oro

Regla de oro de Arch: nunca ejecutes pacman -Sy paquete (refrescar el índice e instalar sin actualizar el resto). Eso es una actualización parcial: el paquete nuevo puede necesitar librerías más recientes que las que tienes y el sistema puede quedar roto. Siempre pacman -Syu, y si quieres instalar algo: pacman -Syu paquete.

AUR (Arch User Repository)

  • Repositorio de recetas (PKGBUILD) publicadas por usuarios, no de paquetes binarios.
  • Se descarga la receta, se revisa y se compila: makepkg -si.
  • Los "ayudantes" (yay, paru) automatizan el proceso, pero no son oficiales.
git clone https://aur.archlinux.org/yay.git
cd yay ; less PKGBUILD   # LEER antes de construir
makepkg -si

Mantenimiento

  • Antes de actualizar tras semanas sin hacerlo: leer las noticias en archlinux.org/news.
  • Si falla la firma: actualizar primero archlinux-keyring.
  • pacman-contrib aporta checkupdates (ver novedades sin tocar la base de datos local) y paccache (limpiar caché).
  • No existe un "unattended-upgrades" oficial: la filosofía es que el administrador decida cuándo actualizar.
El AUR es el equivalente (más arriesgado) de los PPA/COPR: código de terceros sin revisión oficial. En un equipo de empresa, no.

9 · OTROS

Otros gestores: zypper, apk, Flatpak y Snap

Más distros, mismas ideas

GestorInstalarActualizar
zypper (openSUSE/SLES)zypper install xzypper refresh && zypper update
apk (Alpine)apk add xapk update && apk upgrade
dnf (Rocky/Alma/RHEL)dnf install xdnf upgrade

Rocky, Alma y RHEL usan los mismos comandos que Fedora. Con dnf aprendes toda la familia.

Gestores universales (cualquier distro)

flatpak install flathub org.mozilla.firefox
flatpak update ; flatpak list ; flatpak uninstall org.mozilla.firefox
snap install code --classic ; snap refresh ; snap list
  • Flatpak y Snap empaquetan la aplicación con sus dependencias y la ejecutan aislada (sandbox).
  • Mismo paquete en Ubuntu, Fedora y Arch; las versiones no dependen de la distro.
  • Coste: más espacio, y la integración con el sistema puede ser menor.
Es la misma tensión que ya viste con winget frente a instaladores .exe: repositorio común y verificado frente a "cada programa trae lo suyo".

9c · CUANDO ALGO FALLA

Reparar apt: --fix-missing y --fix-broken

--fix-missing

Qué hace: le dice a apt que, si no puede descargar alguno de los paquetes (error 404, "Failed to fetch", "Unable to fetch some archives"), no se detenga: ignora los que faltan y sigue con el resto.

Por qué pasa:

  • Olvidaste apt update y el índice apunta a versiones que el servidor ya retiró (el caso más común).
  • El espejo está sincronizándose o va lento.
  • Se cortó la red a mitad de la descarga.
sudo apt update                          # 1º: refrescar el índice (suele bastar)
sudo apt install --fix-missing nombre   # 2º: si sigue fallando, continuar sin lo que falta
sudo apt upgrade --fix-missing

--fix-broken (-f)

Qué hace: repara un sistema con dependencias rotas: instala las que faltan o elimina los paquetes que no se pueden satisfacer. Distinto del anterior: --fix-missing arregla descargas; -f arregla dependencias.

sudo apt --fix-broken install     # = apt -f install
sudo dpkg --configure -a          # terminar instalaciones interrumpidas
sudo apt clean ; sudo apt update  # vaciar caché de .deb y reintentar

Típico: instalas un .deb con dpkg -i, faltan dependencias y apt se queja; apt -f install las trae.

Ojo: --fix-missing no es un parche mágico. Al saltarse paquetes puede dejar una instalación incompleta. Orden recomendado: 1) apt update · 2) reintentar · 3) --fix-missing · 4) apt -f install al terminar para comprobar que no queda nada roto.

11 · AUTOMATIZACIÓN

Un script que funciona en cualquier distro

El archivo /etc/os-release identifica la distribución: ID es la propia y ID_LIKE la familia de la que desciende.

$ cat /etc/os-release | head -4
NAME="Ubuntu"            # Fedora: ID=fedora   Arch: ID=arch   Rocky: ID="rocky" ID_LIKE="rhel centos fedora"
ID=ubuntu
ID_LIKE=debian
VERSION_ID="24.04"
#!/bin/sh
# instalar.sh — instala paquetes con el gestor de la distro actual
. /etc/os-release
SUDO=""; [ "$(id -u)" -eq 0 ] || SUDO="sudo"      # no usar sudo si ya somos root (contenedores)
case "$ID $ID_LIKE" in
  *debian*|*ubuntu*) $SUDO apt-get update && $SUDO apt-get install -y "$@" ;;
  *fedora*|*rhel*)   $SUDO dnf install -y "$@" ;;
  *arch*)            $SUDO pacman -Syu --needed --noconfirm "$@" ;;
  *) echo "Distro no soportada: $ID" >&2; exit 1 ;;
esac
Fíjate en que en la rama de Arch usamos -Syu y no -S: aplicamos la regla de oro aunque solo queramos instalar un paquete. Este es el tipo de cosa que hacen herramientas como Ansible (ansible.builtin.package) para gestionar flotas de equipos con distros distintas.
12 · PREGUNTAS

Compruébate (haz clic para ver la respuesta)

1. En Fedora, ¿qué comando te dice a qué paquete pertenece /usr/bin/ssh? ¿Y en Arch? (clic)
rpm -qf /usr/bin/ssh en Fedora y pacman -Qo /usr/bin/ssh en Arch. En Ubuntu: dpkg -S /usr/bin/ssh. Los tres consultan la base de datos local de paquetes.
2. Un compañero ejecuta sudo pacman -Sy gimp y después el sistema deja de arrancar bien. ¿Qué ha pasado? (clic)
Actualización parcial: refrescó el índice a la última versión, pero solo instaló GIMP sin actualizar el resto. GIMP (o sus librerías) exigía versiones más nuevas que las instaladas y el sistema quedó inconsistente. Lo correcto: pacman -Syu gimp.
3. ¿Qué equivalente tiene apt purge x && apt autoremove en Arch? (clic)
sudo pacman -Rns x: quita el paquete (-R), sus dependencias que nadie más usa (-s) y los archivos de configuración guardados (-n).
4. Tu empresa pone 40 portátiles. ¿Qué distro de las tres elegirías y por qué? (clic)
Respuesta razonada, normalmente Ubuntu LTS (o Rocky/Alma si la empresa ya usa Red Hat): versión fija con soporte largo, actualizaciones automáticas de seguridad, mucha documentación y soporte comercial disponible. Arch exigiría supervisión constante; Fedora tiene ciclo corto (~13 meses de soporte) y obliga a migrar con frecuencia.
5. ¿Qué diferencia hay entre dnf upgrade y dnf check-update? ¿Se parece a la de apt update y apt upgrade? (clic)
check-update solo informa de qué hay disponible; upgrade instala. Es parecido, pero en dnf los metadatos se refrescan automáticamente cuando caducan, por lo que no existe el error de "instalar sin hacer update" tan típico de apt.
13 · RESUMEN

Para llevarse a casa

  1. Todas las distros tienen un gestor con las mismas cinco acciones: refrescar, actualizar, instalar, quitar y consultar.
  2. Debian/Ubuntu: apt + dpkg. Red Hat/Fedora: dnf + rpm. Arch: pacman.
  3. Consultas útiles: dpkg -S/-L ↔ rpm -qf/-ql ↔ pacman -Qo/-Ql.
  4. En Arch, nunca -Sy sin -u. El AUR es código de terceros: leer el PKGBUILD.
  5. Repositorios firmados (GPG) siempre; PPA, COPR y AUR son "confía en quien lo publica".
  6. Actualizaciones automáticas: unattended-upgrades ↔ dnf-automatic ↔ (nada en Arch) ↔ Windows Update.
  7. Un script portable lee /etc/os-release y elige el gestor.
