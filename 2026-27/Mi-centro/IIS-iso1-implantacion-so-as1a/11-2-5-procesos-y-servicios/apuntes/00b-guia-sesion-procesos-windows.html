1. Procesos en Windows

Una receta y un cocinero. Un programa es la receta (un archivo). Un proceso es esa receta en marcha: tiene un número (PID), un dueño y un padre. Es lo mismo que en Linux.

El árbol de procesos

System (PID 4)
 └─ smss.exe → wininit.exe
                └─ services.exe
                     ├─ svchost.exe   ← aloja varios servicios
                     ├─ svchost.exe
                     └─ spoolsv.exe   ← el servicio de impresión

svchost.exe no es un virus ni un programa concreto: es un contenedor donde Windows ejecuta varios servicios a la vez. Es sospechoso solo si no cuelga de services.exe o no está en C:\Windows\System32.

2. Misión 5 · Procesos de un usuario

Hay que cerrar solo los procesos de ana, sin tocar los tuyos.

Abre una consola que actúe como ana: 
runas /user:ana cmd
Te pedirá su contraseña. En la consola nueva abre tres Bloc de notas: 
start notepad
start notepad
start notepad
Y en tu sesión, abre un Bloc de notas tuyo.
Localiza los de ana (en PowerShell de administrador): 
tasklist /FI "USERNAME eq ana"
Get-Process notepad -IncludeUserName
Si tasklist no filtra, añade /V. Para -IncludeUserName la consola debe estar elevada.
Cierra solo los de ana, en una línea: 
Get-Process notepad -IncludeUserName | Where UserName -like '*\ana' | Stop-Process
Comprueba que solo queda el tuyo: 
tasklist /FI "IMAGENAME eq notepad.exe"
Los cinco procesos que más memoria usan: 
Get-Process | Sort WS -Descending | Select -First 5 Name,Id,@{n='MB';e={[int]($_.WS/1MB)}}
¿Qué servicios aloja el svchost más pesado? Sustituye 1234 por su PID: 
tasklist /SVC /FI "PID eq 1234"
Por qué '*\ana' y no '*ana': el nombre aparece como EQUIPO\ana. Con *ana también coincidiría con un usuario llamado «luisana».
Stop-Process da «Acceso denegado». ¿Qué pasa? (clic para ver la respuesta)
La consola de PowerShell no está elevada. Ábrela con clic derecho → Ejecutar como administrador.
Se cerraron todos los Bloc de notas, también el tuyo. ¿Qué falló? (clic para ver la respuesta)
El filtro por usuario. Hay que usar Where UserName -like '*\ana' antes de Stop-Process.

3. Servicios en Windows

Un servicio es un proceso sin ventana que arranca con el sistema, antes de que nadie inicie sesión. Se gestiona con services.msc, Get-Service y sc.exe.

Por seguridad, no solo por memoria: ha tenido vulnerabilidades graves (PrintNightmare). Lo que no se usa se deshabilita.

4. Misión 6 · Deshabilitar el Spooler (Windows Server)

Mira el estado actual: 
Get-Service Spooler
sc.exe qc spooler
sc.exe query spooler
Párarlo y deshabilítalo (CMD de administrador): 
sc.exe stop spooler
sc.exe config spooler start= disabled
sc.exe qc spooler
Hay un espacio después de start=. Debe salir START_TYPE : 4 DISABLED. En PowerShell sería: 
Stop-Service Spooler
Set-Service Spooler -StartupType Disabled
Reinicia el servidor y demuestra que no vuelve: 
sc.exe query spooler
Debe salir STATE : 1 STOPPED.
Lista los servicios que están en Automático y no están corriendo: 
Get-Service | Where {$_.StartType -eq 'Automatic' -and $_.Status -ne 'Running'}
Alguno es normal (por ejemplo los de «inicio retardado»). Comenta la lista, no solo la pegues.
Busca en el Visor de eventos el evento 7036 del Spooler: 
Get-WinEvent -FilterHashtable @{LogName='System';Id=7036} -MaxEvents 50 | Where {$_.Message -match 'Spooler|Cola de impresión'} | Select -First 5 TimeCreated,Message
Debe aparecer: El servicio Cola de impresión entró en el estado Detenido.
Si no aparece el evento 7036: solo se genera cuando el servicio cambia de estado. Búscalo justo después de hacer el stop.
Si fallaCausa probable
sc stop da error raro en PowerShellEstás usando el alias sc; escribe sc.exe
sc.exe config da errorFalta el espacio después de start=
«Acceso denegado»Consola sin elevar
El Spooler vuelve tras el reinicioSolo hiciste stop, no config start= disabled

5. Misión 7 · Tu propio servicio (remate)

Un .ps1 o un .bat no puede ser un servicio de Windows directamente. Hay dos soluciones aceptadas: un envoltorio como NSSM (hay que descargarlo) o una tarea del Programador de tareas que arranque con el sistema. Aquí usamos la segunda, que no necesita descargar nada.

Crea las carpetas y el script: 
mkdir C:\Scripts
mkdir C:\Logs
Contenido de C:\Scripts\monitor.ps1: 
while ($true) {
  Get-Date | Out-File -Append C:\Logs\monitor.log
  Start-Sleep -Seconds 30
}
Crea la tarea (en Windows PowerShell 5.1, el icono azul, como administrador): 
$a = New-ScheduledTaskAction -Execute 'powershell.exe' -Argument '-NoProfile -ExecutionPolicy Bypass -File C:\Scripts\monitor.ps1'
$t = New-ScheduledTaskTrigger -AtStartup
$s = New-ScheduledTaskSettingsSet -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1) -ExecutionTimeLimit ([TimeSpan]::Zero)
Register-ScheduledTask -TaskName MonitorLog -Action $a -Trigger $t -Settings $s -User 'SYSTEM' -RunLevel Highest
Start-ScheduledTask -TaskName MonitorLog
-AtStartup la lanza con el sistema; -RestartCount 3 la reinicia si falla; -ExecutionTimeLimit ([TimeSpan]::Zero) evita que Windows la mate a las 72 horas.
Compruébalo: 
Get-ScheduledTask MonitorLog | Select TaskName,State
Get-Content C:\Logs\monitor.log -Tail 3
Reinicia y comprueba que el log sigue creciendo sin que hayas hecho nada.
Alternativa con NSSM (si puedes descargarlo)
nssm install MonitorLog "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe" "-File C:\Scripts\monitor.ps1"
sc.exe failure MonitorLog reset= 60 actions= restart/5000
nssm start MonitorLog

Con NSSM aparece en services.msc; con el Programador de tareas, no.

¿En qué se diferencia una tarea programada de un servicio de verdad? (clic para ver la respuesta)
Un servicio aparece en services.msc, tiene estados y se gestiona con sc.exe o Get-Service. Una tarea está en el Programador de tareas y se gestiona con schtasks o Get-ScheduledTask. En la práctica hay que justificar cuál elegiste.

Register-ScheduledTask no existeEstás en PowerShell 7; abre Windows PowerShell (icono azul)
El log no creceNo existe C:\Logs. Mira Get-ScheduledTaskInfo MonitorLog: LastTaskResult distinto de 0 es un fallo
El script no arrancaPolítica de ejecución: por eso -ExecutionPolicy Bypass

Ideas clave

  1. Mismo concepto que en Linux, otras herramientas: tasklist/Get-Process para ver, Stop-Process para terminar.
  2. Se filtra por usuario antes de cerrar nada, y se comprueba después.
  3. Estado y tipo de inicio son cosas distintas, como is-active e is-enabled: se comprueba reiniciando.
  4. En PowerShell, sc no es el comando de servicios: usa sc.exe.
  5. Lo que no se usa se deshabilita: seguridad, no solo rendimiento.
