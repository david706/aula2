1 · CONCEPTOS

Proceso, servicio, demonio

Proceso

Un programa en ejecución: tiene PID, un padre (PPID), un usuario dueño, memoria y CPU asignadas y un estado (ejecutando, durmiendo, parado, zombi).

Todo proceso desciende de PID 1: systemd en Linux; en Windows, System (PID 4) y wininit/services.exe.

Servicio / demonio

Un proceso que arranca sin usuario, suele vivir todo el tiempo que el sistema está encendido y ofrece algo (SSH, web, impresión, hora). En Linux se llaman demonios (sshd, cron); en Windows, servicios (Spooler, W32Time).

Lo gestiona un administrador de servicios: systemd / Service Control Manager.

El CE c) de RA2: actuar sobre servicios y procesos en función de las necesidades del sistema: ver qué corre, parar lo que sobra, arrancar lo que falta y que sobreviva a un reinicio.

2 · LINUX · VER

Ver procesos: ps, top, htop, pstree

ps aux                       # todos los procesos, formato BSD
ps -ef                       # todos, formato System V (muestra PPID)
ps -u ana                    # los de un usuario
ps aux --sort=-%mem | head   # los que más memoria usan
pgrep -a sshd                # PID por nombre
pstree -p                    # árbol
top                          # en vivo: P ordena por CPU, M por memoria, k mata, q sale
htop                         # top con colores (apt install htop)

3 · LINUX · ACTUAR

Señales, prioridad, primer y segundo plano

# señales
kill PID            # SIGTERM (15): "termina cuando puedas"
kill -9 PID         # SIGKILL: el kernel lo elimina; último recurso (no cierra archivos)
kill -STOP PID / kill -CONT PID   # pausar / continuar
killall nombre      # todos los procesos con ese nombre
pkill -u pedro      # todos los de un usuario
# prioridad (nice: -20 máxima … 19 mínima; solo root baja)
nice -n 10 ./backup.sh
renice -n 5 -p PID
# trabajos de la shell
comando &           # en segundo plano
Ctrl+Z → bg / fg    # parar, mandar atrás, traer
jobs
nohup comando &    # sobrevive al cierre de la terminal
🤔 ¿Por qué no usar siempre kill -9? (clic)
Porque el proceso no recibe la señal: no cierra archivos, no borra temporales, no avisa a sus hijos. Primero 15; si en unos segundos no muere, 9.
4 · LINUX · SYSTEMD

Servicios: systemctl

systemctl status ssh            # estado, PID, últimas líneas de log
sudo systemctl start|stop|restart|reload ssh
sudo systemctl enable ssh       # arranca al iniciar el sistema
sudo systemctl disable ssh
sudo systemctl enable --now ssh # enable + start
systemctl is-active ssh ; systemctl is-enabled ssh
systemctl list-units --type=service            # cargados
systemctl list-unit-files --type=service       # todos, con enabled/disabled
systemctl --failed                             # los que han fallado
sudo systemctl mask cups        # imposibilitar arrancarlo (enlace a /dev/null)
start ≠ enable. start arranca ahora; enable lo deja programado para el próximo arranque. Un servicio "started" pero "disabled" desaparece al reiniciar. En el examen y en la práctica se comprueba reiniciando.

Las unidades viven en /lib/systemd/system/*.service (del paquete) y /etc/systemd/system/ (tuyas o modificadas). Tras editar: sudo systemctl daemon-reload.

5 · LINUX · UNIDAD

Crear tu propio servicio

# /etc/systemd/system/monitor-conta.service
[Unit]
Description=Vigila /srv/contabilidad y registra cambios
After=network.target

[Service]
Type=simple
User=root
ExecStart=/usr/local/bin/monitor-conta.sh
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
sudo chmod 755 /usr/local/bin/monitor-conta.sh
sudo systemctl daemon-reload
sudo systemctl enable --now monitor-conta
systemctl status monitor-conta
journalctl -u monitor-conta -f

journalctl: -u unidad, -b (desde el arranque), -f (seguir), --since "1 hour ago", -p err (solo errores).

Es el mismo script de la práctica: un bucle con sleep que escribe en un log. Insistir en Restart=on-failure y en que User= es quién ejecuta el servicio (mínimo privilegio).

6 · WINDOWS · PROCESOS

Administrador de tareas, tasklist, PowerShell

Gráfico

  • Administrador de tareas (Ctrl+Mayús+Esc): Procesos, Rendimiento, Usuarios, Detalles (PID, prioridad, finalizar árbol), Servicios.
  • Monitor de recursos (resmon): CPU, disco, red por proceso.

CMD

tasklist
tasklist /FI "USERNAME eq ana"
tasklist /SVC            :: qué servicios lleva cada svchost
taskkill /PID 1234
taskkill /IM notepad.exe /F /T   :: por nombre, forzado, con hijos
start /LOW programa.exe  :: prioridad

PowerShell

Get-Process
Get-Process | Sort-Object CPU -Descending | Select -First 5
Get-Process -Name notepad | Stop-Process
Stop-Process -Id 1234 -Force
(Get-Process notepad).PriorityClass = "BelowNormal"
Get-Process | Where-Object {$_.WorkingSet -gt 200MB}

Windows no tiene "señales": Stop-Process/taskkill sin /F pide cerrar; con /F es el kill -9.

7 · WINDOWS · SERVICIOS

services.msc, sc, Get-Service

:: CMD
sc.exe query spooler
sc.exe start spooler / sc.exe stop spooler
sc.exe config spooler start= disabled      :: OJO al espacio tras "start="
sc.exe config spooler start= auto | demand | delayed-auto
sc.exe qc spooler                          :: configuración (binario, cuenta, tipo de inicio)
net start / net stop spooler
# PowerShell
Get-Service | Where Status -eq Running
Get-Service -Name Spooler | Select Name,Status,StartType
Restart-Service Spooler
Set-Service Spooler -StartupType Disabled
Get-Service | Where {$_.StartType -eq 'Automatic' -and $_.Status -ne 'Running'}  # deberían estar y no están

services.msc: tipo de inicio (Automático, Automático-retrasado, Manual, Deshabilitado), cuenta con la que corre (Sistema local, Servicio de red, Servicio local, una cuenta de usuario), pestaña Recuperación (qué hacer si falla: reiniciar el servicio, ejecutar un programa) y Dependencias.

Registro: Visor de eventos → Sistema, origen Service Control Manager, IDs 7036 (cambió de estado), 7000/7001 (no pudo arrancar).

9 · RESUMEN

Para llevarse a casa

  1. Proceso = programa en ejecución con PID y dueño; servicio = proceso sin usuario gestionado por systemd / SCM.
  2. Primero kill (15), luego -9. En Windows, /F es el -9.
  3. start no es enable: comprueba reiniciando.
  4. Un servicio debe correr con la cuenta de mínimo privilegio que necesite.
  5. Cuando algo no arranca: systemctl status + journalctl -u / Visor de eventos 7000.
  6. Desactivar lo que no se usa reduce superficie de ataque y consumo (portátiles: lo retomamos en la S25).
