Red TCP/IP en un cliente Ubuntu con Netplan

Criterio de evaluación: RA2.d

Objetivo: configurar la red TCP/IP de un cliente Ubuntu Desktop con Netplan (IP, máscara, puerta de enlace y DNS), comprobar que funciona y saber diagnosticar los errores típicos.

1. Los cuatro datos que necesita un equipo para tener red

Dato Para qué sirve Ejemplo
Dirección IPIdentifica al equipo en la red. No puede repetirse dentro de la misma red.192.168.100.50
MáscaraSepara la parte de red de la parte de equipo. Así el equipo sabe quién es su vecino./24 = 255.255.255.0
Puerta de enlaceRouter al que se envía todo lo que va fuera de mi red (por ejemplo, a Internet). Solo debe haber una.192.168.100.1 en una oficina real
DNSTraduce nombres a IP (google.com → 142.250.x.x).8.8.8.8, 8.8.4.4

Para recordar: IP → quién soy · Máscara → quién es mi vecino · Puerta de enlace → por dónde salgo · DNS → cómo traduzco nombres.

1.1 La máscara: ¿vecino o hay que salir?

Con /24 los tres primeros números son la red. En 192.168.100.0/24 los equipos van del .1 al .254 (el .0 es la dirección de red y el .255 la de difusión).

CIDRMáscaraEquipos posibles
/8255.0.0.016.777.214
/16255.255.0.065.534
/24255.255.255.0254

Ejemplo: 192.168.100.50/24 quiere hablar con 192.168.100.10 → misma red, se hablan directamente. Si quiere hablar con 8.8.8.8 → otra red, el paquete va a la puerta de enlace.

Resumen rápido: clases de IP, públicas y privadas

Las IPv4 se agrupaban en clases según el primer número. Hoy se usa CIDR (la máscara puede ser cualquiera), pero las clases siguen usándose para hablar de las redes.

Clase Primer número Máscara por defecto Rango privado
A1 – 126/8 · 255.0.0.010.0.0.0 – 10.255.255.255
B128 – 191/16 · 255.255.0.0172.16.0.0 – 172.31.255.255
C192 – 223/24 · 255.255.255.0192.168.0.0 – 192.168.255.255
D224 – 239Multidifusión (multicast): un emisor, varios receptores
E240 – 255Experimental, no se usa
  • IP privada: solo vale dentro de una red local. No circula por Internet y se puede repetir en otras empresas. Para salir a Internet, el router la traduce a su IP pública (NAT).
  • IP pública: única en todo Internet. La asigna el proveedor (ISP). Ejemplo: 8.8.8.8.
  • Direcciones especiales: 127.0.0.1 loopback (el propio equipo; por eso el 127 no está en la clase A) · 169.254.x.x APIPA (sin DHCP) · 0.0.0.0 «cualquier red» (ruta por defecto) · 255.255.255.255 difusión.

Nuestra red 192.168.100.0/24 es privada de clase C.

2. Nuestro escenario: la red de la Ferretería Aragón

Cada máquina virtual tiene dos adaptadores de red en VirtualBox:

Equipo Adaptador 1 · NAT Adaptador 2 · Red interna ferreteria
Ubuntu ServerDHCP (10.0.2.x)192.168.100.10/24
Windows ServerDHCP (10.0.2.x)192.168.100.11/24
Ubuntu Desktop (este tema)DHCP (10.0.2.x) · enp0s3192.168.100.50/24 · enp0s8
Windows 11DHCP (10.0.2.x)192.168.100.51/24
  • El NAT (adaptador 1) da la salida a Internet. Por DHCP recibe IP, puerta de enlace (10.0.2.2) y DNS. No se toca.
  • La red interna (adaptador 2) une las máquinas de la ferretería entre sí. No tiene servidor DHCP, así que la IP se pone a mano (estática).
  • En la red interna no se pone puerta de enlace: la puerta de enlace ya la da el NAT. Si pones otra, tendrás dos rutas por defecto y puedes quedarte sin Internet.

En una ferretería real solo habría una tarjeta de red y un router en 192.168.100.1: ahí sí pondríamos esa puerta de enlace en el cliente. En el laboratorio el papel del router lo hace el NAT de VirtualBox.

3. Ver la configuración actual

ip -br a          # resumen: interfaz, estado, IP
ip a              # detalle (incluye la MAC: link/ether)
ip route          # tabla de rutas (la línea "default" es la puerta de enlace)
route -n          # lo mismo, formato clásico (paquete net-tools)
resolvectl dns    # servidores DNS de cada interfaz

Antes de configurar, la salida de ip -br a será parecida a:

lo        UNKNOWN  127.0.0.1/8 ::1/128
enp0s3    UP       10.0.2.15/24 ...      ← NAT, por DHCP
enp0s8    UP                             ← red interna, sin IP todavía

Si tu interfaz interna no se llama enp0s8, usa el nombre que veas. Si no aparece, el adaptador 2 no está habilitado en VirtualBox.

4. ¿Qué es Netplan?

Netplan es el sistema de configuración de red de Ubuntu. Escribimos la configuración en un archivo YAML dentro de /etc/netplan/ y Netplan se la pasa a un renderer, que es quien gestiona la red de verdad:

  • NetworkManager → Ubuntu Desktop (nuestro caso).
  • networkd → Ubuntu Server.

Todos los .yaml de /etc/netplan/ se leen en orden alfabético y se combinan. En Ubuntu Desktop suele existir ya 01-network-manager-all.yaml. Nosotros crearemos /etc/netplan/01-netcfg.yaml.

4.1 Reglas de YAML (la causa de casi todos los errores)

  • La sangría marca la estructura: espacios, 2 por nivel. Nunca tabuladores.
  • Detrás de : va un espacio: dhcp4: false.
  • Las listas van entre corchetes [a, b] o con guion - a en líneas separadas.
  • Distingue mayúsculas y minúsculas: enp0s8 ≠ Enp0s8.

5. El archivo de configuración

# /etc/netplan/01-netcfg.yaml
network:
  version: 2
  renderer: NetworkManager
  ethernets:
    enp0s3:
      dhcp4: true                  # NAT: lo da todo por DHCP
    enp0s8:
      dhcp4: false                 # red interna: IP fija
      addresses:
        - 192.168.100.50/24        # IP + máscara
      nameservers:
        addresses: [8.8.8.8, 8.8.4.4]
      # sin puerta de enlace: la da el NAT
Clave Significado
network:Raíz obligatoria.
version: 2Versión del formato. Siempre 2.
renderer: NetworkManagerQuién aplica la configuración (Desktop).
ethernets:Tarjetas de red por cable. (También existen wifis:, bridges:…)
dhcp4: true / falseActiva o desactiva DHCP en IPv4.
addresses:IP con su máscara en formato CIDR. La máscara va incluida (/24).
nameservers: addresses:Servidores DNS.
routes: - to: default via: XPuerta de enlace. No la usamos en la red interna.

5.1 Cómo se escribe la puerta de enlace (cuando sí hace falta)

En una red con router propio, por ejemplo la ferretería real con una sola tarjeta:

    enp0s3:
      dhcp4: false
      addresses: [192.168.100.50/24]
      routes:
        - to: default
          via: 192.168.100.1
      nameservers:
        addresses: [8.8.8.8, 8.8.4.4]

En tutoriales antiguos verás gateway4: 192.168.100.1. Funciona, pero está obsoleto: Netplan avisa "gateway4 has been deprecated". Usa routes.

6. Editar y aplicar

ls -l /etc/netplan/                              # qué archivos hay
sudo nano /etc/netplan/01-netcfg.yaml            # Ctrl+O, Intro, Ctrl+X
sudo chmod 600 /etc/netplan/01-netcfg.yaml       # solo root puede leerlo
sudo netplan generate                            # comprueba la sintaxis, no aplica
sudo netplan try                                 # aplica; si no pulsas Intro en 120 s, vuelve atrás
sudo netplan apply                               # aplica de forma definitiva
  • chmod 600: repaso de la sesión de permisos → lectura y escritura solo para el propietario (root). Si no lo haces, Netplan avisa "Permissions ... are too open".
  • netplan try es tu red de seguridad: si te quedas sin conexión, la configuración anterior vuelve sola.
  • Para ver la configuración combinada de todos los archivos: sudo netplan get.

7. Comprobar que funciona

Comprueba siempre de dentro hacia fuera:

Comando Qué compruebo Resultado correcto
ip -br aIP y máscaraenp0s8 UP 192.168.100.50/24
ip route / route -nPuerta de enlaceUna sola línea default via 10.0.2.2 dev enp0s3 y una línea 192.168.100.0/24 dev enp0s8. En route -n: una sola fila 0.0.0.0 con flags UG.
resolvectl dnsDNSLink ... (enp0s8): 8.8.8.8 8.8.4.4
ping -c 4 192.168.100.10Llego al servidor de la ferretería4 received, 0% packet loss
ping -c 4 8.8.8.8Salgo a Internet0% packet loss
nslookup google.comResuelvo nombresLíneas Name: google.com y Address: ...
  • ping en Linux no para solo: usa -c 4 o Ctrl+C.
  • Si route -n no existe: sudo apt install net-tools (o usa ip route). Si nslookup no existe: sudo apt install dnsutils.
  • Es normal que nslookup muestre Server: 127.0.0.53: es systemd-resolved, un intermediario local que reenvía la consulta a los DNS reales.

8. ¿Y en otras distribuciones?

Netplan es propio de Ubuntu. Cada familia de Linux usa su herramienta, pero los cuatro datos son los mismos y los comandos de comprobación (ip a, ip route, ping) funcionan en todas.

Distribución Herramienta Dónde se guarda Aplicar
UbuntuNetplan (+ NetworkManager o networkd)/etc/netplan/*.yamlnetplan apply
Fedora / RHEL / RockyNetworkManager (nmcli, nmtui)/etc/NetworkManager/system-connections/*.nmconnectionnmcli con up
Arch LinuxLo eliges tú: systemd-networkd o NetworkManager/etc/systemd/network/*.networknetworkctl reload
Debian (clásico)ifupdown/etc/network/interfacessystemctl restart networking

8.1 Fedora con nmcli

nmcli device status                         # interfaces y su estado
sudo nmcli con add type ethernet ifname enp0s8 con-name ferreteria \
     ipv4.method manual ipv4.addresses 192.168.100.50/24 \
     ipv4.dns "8.8.8.8 8.8.4.4"
sudo nmcli con up ferreteria
nmcli con show ferreteria | grep ipv4

Con puerta de enlace se añadiría ipv4.gateway 192.168.100.1. Si prefieres menús en la terminal: nmtui. Esto también funciona en Ubuntu Desktop, porque usa NetworkManager.

8.2 Arch Linux con systemd-networkd

Archivo /etc/systemd/network/20-ferreteria.network:

[Match]
Name=enp0s8

[Network]
Address=192.168.100.50/24
DNS=8.8.8.8
DNS=8.8.4.4
# Gateway=192.168.100.1   (solo si hiciera falta)
sudo systemctl enable --now systemd-networkd systemd-resolved
sudo networkctl reload
networkctl status enp0s8

Arch no trae nada configurado de serie: tras instalarlo, eres tú quien activa el gestor de red. No mezcles networkd y NetworkManager sobre la misma interfaz.

8.3 Debian clásico

# /etc/network/interfaces
auto enp0s8
iface enp0s8 inet static
    address 192.168.100.50/24
    # gateway 192.168.100.1   (solo si hiciera falta)

Los DNS se ponen en /etc/resolv.conf (nameserver 8.8.8.8). Se aplica con sudo systemctl restart networking.

8.4 Cambio temporal (cualquier distribución)

sudo ip addr add 192.168.100.50/24 dev enp0s8
sudo ip link set enp0s8 up
sudo ip route add default via 192.168.100.1    # solo si hiciera falta

Sirve para hacer pruebas rápidas, pero se pierde al reiniciar. Para que sea permanente hay que usar la herramienta de la distribución.

9. Errores típicos y cómo resolverlos

Error 1 · Sangría incorrecta. addresses no está alineada con dhcp4, así que Netplan no sabe a qué interfaz pertenece:

    enp0s8:
      dhcp4: false
     addresses: [192.168.100.50/24]     ← 5 espacios; deben ser 6

Qué verás: netplan generate o try muestran un error de YAML indicando línea y columna. Solución: ve a esa línea, alinea con espacios (nunca tabuladores) y repite.

Error 2 · Falta el espacio tras los dos puntos.

      dhcp4:false                       ← debe ser  dhcp4: false

Qué verás: error de sintaxis YAML con número de línea. Solución: añade el espacio.

Error 3 · Falta la máscara.

      addresses: [192.168.100.50]       ← falta /24

Qué verás: Netplan indica que a la dirección le falta la longitud del prefijo. Solución: escribe 192.168.100.50/24.

Error 4 · Puerta de enlace en la red interna. Añadir routes: - to: default via: 192.168.100.1 en enp0s8.

Qué verás: Netplan no da error, pero ip route muestra dos líneas default. Si gana la de la red interna, ping 8.8.8.8 falla porque en 192.168.100.1 no hay ningún router. Solución: quita el bloque routes de enp0s8 y vuelve a aplicar.

Error 5 · Configurar la interfaz equivocada. Poner la IP fija en enp0s3 (NAT) en vez de en enp0s8.

Qué verás: se pierde Internet (el NAT deja de dar IP y puerta de enlace) y enp0s8 sigue sin IP. Solución: enp0s3 con dhcp4: true y la IP fija en enp0s8.

Error 6 · La IP no aparece tras aplicar.

Causas: nombre de interfaz mal escrito, olvidaste netplan apply, otro archivo de /etc/netplan/ configura la misma interfaz (compruébalo con sudo netplan get), o el adaptador 2 está deshabilitado en VirtualBox (la interfaz no aparece o está DOWN).

Error 7 · Hay ping a 8.8.8.8 pero no a google.com.

Causa: falla el DNS. Revisa nameservers (que esté dentro de la interfaz y con la sangría correcta) y resolvectl dns.

Error 8 · Conflicto de IP. Dos máquinas con la misma IP: la conexión funciona a ratos y se corta.

Cómo detectarlo:

ip neigh          # qué MAC responde a cada IP vecina

Compara la MAC con la de la máquina que debería tener esa IP (link/ether en ip a).

Avisos (no son errores, pero corrígelos): "Permissions ... are too open" → sudo chmod 600 /etc/netplan/*.yaml · "gateway4 has been deprecated" → usa routes.

Escalera de diagnóstico: el primer peldaño que falla te dice qué revisar.

1. ip -br a → ¿tengo IP y la interfaz está UP?No → interfaz, YAML, VirtualBox
2. ping 192.168.100.10 → ¿llego a mi red?No → IP, máscara, adaptador 2
3. ping 8.8.8.8 → ¿salgo a Internet?No → puerta de enlace (ip route)
4. nslookup google.com → ¿resuelvo nombres?No → DNS

Intenta responder antes de abrir cada pregunta para ver la solución.

1. ¿Qué cuatro datos necesita un equipo para tener conectividad completa?
Solución: IP, máscara, puerta de enlace y DNS.
2. Escribe /24 en formato decimal.
Solución: 255.255.255.0.
3. 192.168.100.50/24 quiere hablar con 192.168.100.200. ¿Pasa por la puerta de enlace?
Solución: No: los dos están en 192.168.100.0/24, se hablan directamente.

Solución: Porque la salida a Internet ya la da el NAT; una segunda puerta de enlace crea dos rutas por defecto.
5. Hay ping a 8.8.8.8 pero no a google.com. ¿Qué revisas?
Solución: Los DNS (nameservers, resolvectl dns).
6. ¿Qué diferencia hay entre netplan try y netplan apply?
Solución: try aplica y vuelve atrás si no confirmas en 120 s; apply aplica de forma definitiva.
7. ip route muestra dos líneas default. ¿Qué ha pasado?
Solución: Se ha puesto una puerta de enlace también en la red interna (error 4).
8. Di la clase y si es pública o privada: 10.0.5.3, 172.20.1.1, 8.8.8.8.
Solución: 10.0.5.3 clase A privada · 172.20.1.1 clase B privada · 8.8.8.8 clase A pública.
