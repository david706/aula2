Comparar sistemas operativos en 2026

Elegir un sistema no es cuestión de gustos: se decide por requisitos de hardware, ciclo de soporte, licencia y campo de aplicación. Estos son los datos actuales de los sistemas que usamos en el ciclo.

El programa ESU para particulares se anunció hasta el 13/10/2026; algunas fuentes indican una ampliación a 2027 para equipos ya inscritos. Es un buen ejercicio: que el alumnado lo compruebe en la página oficial de Microsoft y justifique qué haría con un equipo del aula que no cumple los requisitos de Windows 11.

Ciclo de vida: por qué importa

  • LTS / LTSC (Long Term Support): versiones pensadas para servidores y empresas. Cambian poco y reciben parches muchos años.
  • Versiones intermedias (Ubuntu 25.10, por ejemplo): novedades antes, pero soporte corto (9 meses en Ubuntu).
  • Fin de soporte no significa que el sistema deje de funcionar, sino que deja de recibir parches: un equipo conectado a la red se vuelve cada vez más vulnerable.

02

Antes de instalar: firmware, particiones y requisitos

BIOS (legacy)

Firmware antiguo de 16 bits. Arranca leyendo el MBR (primer sector del disco). Sin Secure Boot.

UEFI

Firmware moderno. Arranca un programa .efi desde la partición ESP. Permite Secure Boot, discos GPT grandes y arranque más rápido. Obligatorio para Windows 11.

MBRGPT
Particiones4 primarias (o 3 + extendida con lógicas)128 en Windows, sin extendidas
Tamaño máximo de disco2 TiBPrácticamente ilimitado
RedundanciaNoCopia de la tabla al final del disco + CRC
Firmware habitualBIOSUEFI

Esquema típico de particiones en UEFI + GPT

WINDOWS

ESP (FAT32, ~100–260 MB) · MSR (16 MB, reservada) · C: NTFS · Recuperación (WinRE, ~1 GB).

LINUX

ESP montada en /boot/efi · / ext4 · /home opcional · swap (partición o fichero).

Arranque dual

Instala primero Windows y después Linux: el instalador de Linux detecta Windows y lo añade a GRUB. Al revés, Windows suele tomar el control del arranque.

Lista de comprobación previa

  • Requisitos de hardware y compatibilidad (PC Health Check en Windows; hoja de requisitos de la distribución).
  • Modo de firmware (UEFI/Legacy), Secure Boot y TPM activados si hacen falta.
  • Copia de seguridad de los datos y esquema de particiones decidido.
  • Medio de instalación verificado: la suma SHA256 de la ISO coincide con la oficial.
  • Licencia o clave disponible; controladores de red y almacenamiento a mano.
# Comprobar la integridad de una ISO
$ sha256sum ubuntu-26.04-desktop-amd64.iso
PS> Get-FileHash .\Win11_25H2.iso -Algorithm SHA256
# ¿El equipo arrancó en UEFI?
$ [ -d /sys/firmware/efi ] && echo UEFI || echo BIOS
PS> Confirm-SecureBootUEFI # True si Secure Boot está activo

03

Proceso de instalación y verificación

Fases comunes

  1. Arrancar desde el medio (USB creado con Rufus/Ventoy, o ISO montada en la máquina virtual).
  2. Idioma, teclado y tipo de instalación (limpia o actualización).
  3. Particionado: automático o manual según el esquema del apartado anterior.
  4. Copia de ficheros e instalación del gestor de arranque.
  5. Usuario inicial, nombre del equipo, red y zona horaria.
  6. Primer arranque, controladores y actualizaciones.

En VirtualBox (prácticas del aula)

  • Windows 11: activar EFI, TPM 2.0 y Secure Boot en la configuración de la VM; mínimo 4 GB RAM y 64 GB de disco.
  • Ubuntu: 6 GB RAM recomendados para escritorio; con menos, usar una variante ligera (Lubuntu, Xubuntu) o la versión servidor.
  • Instalar las Guest Additions después, para tener portapapeles compartido, resolución automática y carpetas compartidas.

Verificar que la instalación es correcta

$ hostnamectl # SO, núcleo, arquitectura, virtualización
$ cat /etc/os-release
$ lsblk -f # particiones y sistemas de archivos
PS> winver # versión y compilación de Windows
PS> Get-ComputerInfo | Select-Object OsName, OsVersion, BiosFirmwareType
PS> Get-Disk | Select-Object Number, PartitionStyle, Size

04

Actualizar el sistema y las aplicaciones

WINDOWS

Actualizaciones de calidad: acumulativas, cada mes (el segundo martes, «Patch Tuesday»). Actualizaciones de características: una al año (25H2, 26H2…). En empresa se controlan con WSUS, Intune o directivas.

UBUNTU / DEBIAN

Repositorios + APT. Parches de seguridad continuos; unattended-upgrades los instala solos. Cambio de versión con do-release-upgrade.

$ sudo apt update # refresca la lista de paquetes
$ apt list --upgradable
$ sudo apt upgrade # actualiza sin eliminar paquetes
$ sudo apt full-upgrade # permite quitar/añadir para resolver dependencias
$ sudo snap refresh
PS> winget upgrade # aplicaciones con actualización pendiente
PS> winget upgrade --all
PS> Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 5
Buena práctica de administrador

Antes de una actualización grande: copia de seguridad o punto de restauración, probar primero en una máquina de pruebas y anotarlo en el registro de cambios.

06

El arranque y sus incidencias

Secuencia: encendido → POST (autocomprobación del hardware) → firmware (UEFI/BIOS) → gestor de arranque → núcleo → primer proceso (systemd en Linux; en Windows, smss.exe, wininit.exe y servicios) → inicio de sesión.

WINDOWS BOOT MANAGER

Lee la configuración del almacén BCD en la ESP. Se consulta y edita con bcdedit; se regenera con bcdboot.

GRUB 2

Gestor habitual en Linux. Se configura en /etc/default/grub y /etc/grub.d/; tras cambiar algo hay que regenerar /boot/grub/grub.cfg.

C:\> bcdedit /enum # entradas de arranque
C:\> bcdboot C:\Windows /f UEFI # recrea los ficheros de arranque en la ESP
X:\> bootrec /rebuildbcd # desde WinRE
$ sudo efibootmgr -v # entradas UEFI y orden de arranque
$ sudo nano /etc/default/grub # GRUB_TIMEOUT, GRUB_DEFAULT…
$ sudo update-grub # Debian/Ubuntu; en otras: grub-mkconfig -o /boot/grub/grub.cfg
$ systemd-analyze blame # qué servicios retrasan el arranque
$ journalctl -b -p err # errores del arranque actual
$ journalctl --list-boots

Incidencias típicas

SíntomaCausa probableSolución

07

Ficheros de inicio y registro del sistema

Qué se ejecuta al arrancar

WINDOWS

Servicios (services.msc), claves Run del registro, carpeta shell:startup, Programador de tareas y la pestaña Inicio del Administrador de tareas.

LINUX

Unidades de systemd (/etc/systemd/system), /etc/fstab (montajes), tareas @reboot de cron y ~/.config/autostart en el escritorio.

$ systemctl list-unit-files --state=enabled
$ systemctl status ssh
PS> Get-Service | Where-Object StartType -eq Automatic
PS> Get-CimInstance Win32_StartupCommand | Select-Object Name, Command, Location

El registro de Windows

Base de datos jerárquica donde Windows y las aplicaciones guardan su configuración. Está formado por claves (como carpetas) y valores (nombre, tipo y dato).

Clave raízContenido
HKEY_LOCAL_MACHINE (HKLM)Configuración del equipo: hardware, software, servicios, seguridad.
HKEY_CURRENT_USER (HKCU)Configuración del usuario que ha iniciado sesión.
HKEY_USERS (HKU)Perfiles de todos los usuarios cargados.
HKEY_CLASSES_ROOT (HKCR)Asociaciones de archivos y objetos COM.
HKEY_CURRENT_CONFIG (HKCC)Perfil de hardware actual.

Físicamente se guarda en ficheros llamados hives: SYSTEM, SOFTWARE, SAM, SECURITY en C:\Windows\System32\config, y NTUSER.DAT en el perfil de cada usuario.

C:\> reg query HKLM\Software\Microsoft\Windows\CurrentVersion\Run
C:\> reg export HKCU\Software\MiApp copia_miapp.reg # copia antes de tocar
PS> Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion" | Select-Object ProductName, DisplayVersion, CurrentBuild
Regla de oro con el registro

Exportar la clave antes de modificarla y trabajar siempre en una máquina virtual durante las prácticas. Un cambio erróneo en HKLM puede impedir el arranque.

En Linux no existe un registro central: la configuración está en ficheros de texto (en /etc para todo el sistema y ficheros ocultos en ~ para cada usuario). Por eso es fácil de versionar y copiar.

08

Software instalado, su origen y controladores

El CE g) pide saber qué hay instalado y de dónde viene: repositorio oficial, tienda, paquete descargado a mano… Es la base del inventario y de la seguridad.

# Linux
$ apt list --installed | wc -l
$ apt-cache policy openssh-server # versión y repositorio de origen
$ dpkg -S /usr/bin/ssh # a qué paquete pertenece un fichero
$ snap list ; flatpak list
# Windows
PS> winget list # incluye la columna «Origen» (winget, msstore)
PS> Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\* | Select-Object DisplayName, DisplayVersion, Publisher

Controladores de dispositivos

$ lspci -k # dispositivos PCI y el módulo (driver) que usan
$ lsusb ; lsmod ; sudo dmesg | tail
$ sudo ubuntu-drivers list # controladores privativos recomendados
C:\> driverquery /v
C:\> pnputil /enum-drivers # paquetes de controladores del almacén
PS> Get-PnpDevice -Status Error # dispositivos con problemas

En el Administrador de dispositivos (devmgmt.msc), la opción Revertir controlador vuelve a la versión anterior si una actualización da problemas.
