Gestión de paquetes: instalar y desinstalar software

¿Qué es un gestor de paquetes?

Un gestor de paquetes es la herramienta que instala, actualiza y elimina software de forma controlada, conectándose a un repositorio (un catálogo de programas verificados) y resolviendo automáticamente las dependencias — las otras piezas de software que un programa necesita para funcionar. Es la alternativa moderna a descargar un instalador suelto de cualquier web: todo el software queda registrado, versionado y se puede actualizar o desinstalar de forma limpia desde un único punto.

  • Repositorio: el servidor (o conjunto de servidores) donde vive el catálogo de paquetes disponibles para tu sistema.
  • Paquete: el programa empaquetado junto con sus metadatos — versión, dependencias, dónde debe instalarse cada archivo.
  • Dependencia: otro paquete que el programa necesita para funcionar (una librería, un entorno de ejecución, etc.).
  • Resolución de dependencias: el proceso automático de calcular e instalar todo lo necesario para que un paquete funcione, sin que el usuario tenga que buscarlo a mano.
01

Linux — APT y dpkg

🐧 UBUNTU / DEBIAN

Ubuntu (como toda distribución basada en Debian) trabaja en dos niveles: dpkg, la herramienta de bajo nivel que instala y consulta archivos .deb individuales sin resolver dependencias; y APT (Advanced Package Tool), la capa superior que sí resuelve dependencias automáticamente y gestiona los repositorios. En la práctica, casi todo se hace con APT — dpkg queda para instalar un .deb suelto o depurar problemas.

HerramientaNivelQué hace
aptAlto nivelInstala, actualiza y elimina paquetes desde los repositorios configurados, resolviendo dependencias automáticamente.
dpkgBajo nivelInstala o inspecciona un archivo .deb concreto ya descargado, sin tocar repositorios ni resolver dependencias.

Comandos esenciales de APT

# Actualizar el índice de paquetes disponibles y luego el sistema $ sudo apt update && sudo apt upgrade -y # Instalar un paquete $ sudo apt install htop # Eliminar un paquete (deja los ficheros de configuración) $ sudo apt remove htop # Eliminar un paquete y también su configuración $ sudo apt purge htop # Buscar un paquete por nombre o palabra clave $ apt search "servidor ssh" # Ver información detallada de un paquete antes de instalarlo $ apt show openssh-server # Listar todo lo que hay instalado en el sistema $ apt list --installed # Limpiar dependencias huérfanas y caché de descargas $ sudo apt autoremove && sudo apt autoclean

Así se ve una instalación real — APT calcula las dependencias y pide confirmación antes de tocar el sistema:

$ sudo apt install htop Leyendo lista de paquetes... Hecho Calculando la actualización... Hecho Se instalarán los siguientes paquetes NUEVOS: htop 0 actualizados, 1 nuevos, 0 para eliminar. Se necesita descargar 92,0 kB de archivos. ¿Desea continuar? [S/n] S Descargado 92,0 kB en 0s Seleccionando el paquete htop previamente no seleccionado. Preparando para desempaquetar .../htop_3.3.0-1_amd64.deb ... Desempaquetando htop (3.3.0-1) ... Configurando htop (3.3.0-1) ...

Instalar un .deb suelto con dpkg

# Instalar un paquete .deb descargado manualmente $ sudo dpkg -i programa.deb # Si faltan dependencias, dpkg no las resuelve solo — se lo pedimos a APT $ sudo apt install -f # Listar todos los paquetes instalados que gestiona dpkg $ dpkg -l | less
Nota: en Ubuntu Desktop también encontrarás snap y flatpak, formatos de paquete "universales" que no dependen de APT/dpkg y que instalan cada aplicación con sus propias dependencias aisladas. Se gestionan con sus propios comandos (snap install, flatpak install) — útil para software reciente que aún no está en los repositorios oficiales.

Desde la interfaz gráfica (GUI)

En Ubuntu Desktop, Ubuntu Software (o App Center / GNOME Software, según la versión) permite buscar, instalar y desinstalar paquetes con un catálogo visual, sin escribir un solo comando — usa APT y Snap por debajo. Para un .deb descargado manualmente, hacer doble clic lo abre con el instalador gráfico de paquetes (GDebi o similar), equivalente a dpkg -i con interfaz.

02

Windows — winget

🪟 WINDOWS 10 / 11 / SERVER

winget (Windows Package Manager) es el equivalente de Microsoft a APT: una herramienta de línea de comandos, de código abierto, que instala, actualiza y desinstala software conectándose a un catálogo mantenido por Microsoft y la comunidad — miles de aplicaciones verificadas, desde navegadores hasta herramientas de desarrollo. Viene integrado de serie en Windows 11 y en las versiones modernas de Windows 10 (a través del Instalador de App), así como en Windows Server 2025.

Comandos esenciales de winget

# Buscar una aplicación en el catálogo PS> winget search "7zip" # Instalar una aplicación por nombre o por ID exacto PS> winget install 7zip.7zip # Ver información detallada antes de instalar PS> winget show 7zip.7zip # Listar todo el software instalado en el equipo (lo gestione winget o no) PS> winget list # Comprobar y aplicar actualizaciones disponibles PS> winget upgrade --all # Desinstalar una aplicación PS> winget uninstall 7zip.7zip

Salida real de una instalación con winget:

PS> winget install 7zip.7zip Encontrado 7-Zip [7zip.7zip] Este producto viene con el siguiente acuerdo de licencia... Descargando https://www.7-zip.org/a/7z2409-x64.exe ██████████████████████████████ 1.53 MB / 1.53 MB Se ha completado correctamente la instalación

Clonar la instalación de un equipo a otro

Una de las funciones más útiles de winget para un aula o un parque de equipos: exportar la lista de software instalado e importarla en otro equipo.

# En el equipo origen: guarda la lista de programas instalados PS> winget export -o programas.json # En el equipo destino: reinstala automáticamente todo lo de la lista PS> winget import -i programas.json
Nota: winget instala paquetes en formato .exe, .msi y .msix (el formato moderno de la Microsoft Store). Cuando desinstales una app instalada desde la Store, winget puede pedir confirmación adicional del contrato de la Store — se evita añadiendo --source winget al comando.

Desde la interfaz gráfica (GUI)

Windows ofrece varias vías gráficas equivalentes: Configuración → Aplicaciones → Aplicaciones instaladas (para desinstalar o modificar), la Microsoft Store (para instalar desde un catálogo con actualizaciones automáticas), y el clásico Panel de control → Programas y características (heredado de versiones anteriores, sigue disponible para instaladores .msi tradicionales).

Comparativa: el mismo concepto, dos mundos

La lógica es idéntica en ambos sistemas — repositorio, paquete, dependencias — solo cambia la herramienta y la sintaxis.

Buscar un paqueteapt search nombrewinget search nombre
Instalarsudo apt install nombrewinget install nombre
Ver informaciónapt show nombrewinget show nombre
Listar instaladosapt list --installedwinget list
Actualizar todosudo apt upgradewinget upgrade --all
Desinstalarsudo apt remove nombrewinget uninstall nombre

Mini-práctica: instalar y desinstalar desde ambas vías

Sobre las VMs que ya tenéis instaladas (Ubuntu y Windows), repite esta secuencia primero por línea de comandos y después por interfaz gráfica.

  1. En Ubuntu: instala htop con apt install, compruébalo con apt list --installed | grep htop, y desinstálalo con apt purge.
  2. En Ubuntu: repite la instalación de otro paquete cualquiera, esta vez desde Ubuntu Software (GUI), y compara cuántos clics/comandos ha llevado cada vía.
  3. En Windows: instala una aplicación con winget install, compruébala con winget list, y desinstálala con winget uninstall.
  4. En Windows: repite la instalación desde Configuración → Aplicaciones o la Microsoft Store, y anota las diferencias frente a winget.
