1 · POR QUÉ

La contraseña es la puerta; la política, la cerradura

Un sistema con permisos perfectos cae igual si ana usa ana1234 y nunca la cambia. El CE b) de RA2 pide exactamente esto: asegurar el acceso mediante directivas de cuenta y de contraseñas.

Qué controla una política

  • Calidad: longitud, complejidad, no reutilizar.
  • Vida: caducidad máxima, mínimo entre cambios, aviso previo.
  • Bloqueo: intentos fallidos, duración del bloqueo.
  • Cuenta: caducidad, primer cambio obligatorio, deshabilitar.

3 · LINUX · CHAGE

chage, passwd y usermod

# envejecimiento de una cuenta
sudo chage -M 90 -m 1 -W 7 ana      # máx 90 días, mín 1, aviso 7
sudo chage -d 0 ana                 # obligar a cambiar en el próximo login
sudo chage -E 2027-06-30 luis       # la cuenta caduca ese día (becario)
sudo chage -E -1 luis               # quitar caducidad
sudo chage -l ana                   # consultar
# bloquear / desbloquear
sudo passwd -l pedro                # pone ! delante del hash
sudo passwd -u pedro
sudo usermod -L pedro / -U pedro    # igual
sudo usermod -s /usr/sbin/nologin pedro   # sin shell: no entra por consola/SSH
# valores por defecto para usuarios NUEVOS
sudo nano /etc/login.defs           # PASS_MAX_DAYS 90  PASS_MIN_DAYS 1  PASS_WARN_AGE 7
login.defs solo afecta a cuentas creadas después; a las existentes hay que aplicarles chage una a una (o con un bucle).
4 · LINUX · PAM

Calidad de la contraseña: pam_pwquality

PAM (Pluggable Authentication Modules) es la cadena por la que pasa cualquier login. El módulo pam_pwquality comprueba la contraseña nueva cuando alguien hace passwd.

sudo apt install libpam-pwquality
sudo nano /etc/security/pwquality.conf
minlen = 10          # longitud mínima
dcredit = -1         # al menos 1 dígito
ucredit = -1         # al menos 1 mayúscula
lcredit = -1         # al menos 1 minúscula
ocredit = -1         # al menos 1 símbolo
maxrepeat = 3        # no más de 3 iguales seguidos
usercheck = 1        # no puede contener el nombre de usuario
enforce_for_root     # que también se lo aplique a root

Probar: su - ana → passwd → poner hola → "La contraseña es demasiado corta / BAD PASSWORD". Nota: root con sudo passwd ana se salta las reglas salvo que pongas enforce_for_root; la prueba válida es como el propio usuario.

Si el paquete no instala por falta de red en la VM, recordar que Ubuntu Server 24.04 ya trae pam_pwquality en la cadena common-password (minlen por defecto 8). Comprobar con grep pwquality /etc/pam.d/common-password.

5 · LINUX · BLOQUEO

Bloqueo por intentos fallidos: pam_faillock

sudo nano /etc/security/faillock.conf
deny = 5             # intentos
unlock_time = 600    # segundos bloqueado (0 = hasta que lo desbloquee root)
fail_interval = 900  # ventana en la que se cuentan los fallos
# activar en la cadena PAM (Ubuntu no lo trae activo):
sudo nano /etc/pam.d/common-auth
auth    required   pam_faillock.so preauth
auth    [success=1 default=ignore] pam_unix.so nullok
auth    [default=die] pam_faillock.so authfail
auth    sufficient pam_faillock.so authsucc
# consultar y desbloquear
sudo faillock --user pedro
sudo faillock --user pedro --reset
Editar /etc/pam.d/* a mano puede dejarte fuera del sistema. Mantén una sesión root abierta en otra terminal mientras pruebas, y haz una copia: sudo cp /etc/pam.d/common-auth{,.bak}.

Registro de intentos: sudo journalctl -u ssh o sudo grep "Failed password" /var/log/auth.log, y lastb (logins fallidos) / last (correctos).

6 · WINDOWS · SECPOL

Directiva de seguridad local: secpol.msc

Win+R → secpol.msc → Directivas de cuenta. Se aplica a todas las cuentas locales del equipo (en RA4 lo mismo se hará para todo el dominio con una GPO).

Directiva de contraseñas

  • Longitud mínima (0–14+)
  • Debe cumplir requisitos de complejidad (3 de 4: mayús, minús, dígito, símbolo; sin el nombre)
  • Vigencia máxima / mínima
  • Exigir historial (no repetir las últimas N)
  • Almacenar con cifrado reversible: siempre deshabilitado

Directiva de bloqueo de cuenta

  • Umbral: intentos fallidos
  • Duración del bloqueo (minutos; 0 = hasta que lo desbloquee un admin)
  • Restablecer el contador tras N minutos
  • Permitir bloqueo de Administrador (Win 11 22H2+)
:: lo mismo por línea de comandos
net accounts                     :: ver la política actual
net accounts /minpwlen:10 /maxpwage:90 /minpwage:1 /uniquepw:5
net accounts /lockoutthreshold:5 /lockoutduration:15 /lockoutwindow:15

La complejidad no se puede activar con net accounts: secpol.msc o secedit.

7 · WINDOWS · CUENTAS

Acciones sobre una cuenta

net user ana /logonpasswordchg:yes     :: cambiar contraseña en el próximo inicio
net user ana /passwordchg:no           :: el usuario NO puede cambiarla
net user ana /expires:30/06/2027       :: la cuenta caduca
net user ana /active:no                :: deshabilitar
net user ana /times:L-V,8:00-18:00     :: horas de inicio de sesión
net user ana                           :: ver todo lo anterior
# PowerShell
Set-LocalUser -Name ana -PasswordNeverExpires $false -AccountExpires (Get-Date "2027-06-30")
Disable-LocalUser -Name pedro
Get-LocalUser | Select Name,Enabled,PasswordLastSet,PasswordExpires

Dónde se ven los intentos: Visor de eventos → Registros de Windows → Seguridad, ID 4625 (fallo de inicio de sesión), 4624 (éxito), 4740 (cuenta bloqueada). Hace falta tener activada la auditoría de inicio de sesión (secpol → Directiva de auditoría), que lo retomaremos en RA7.

8 · BUENAS PRÁCTICAS

Lo que dice hoy la seguridad (no lo de hace 15 años)

Recomendado (NIST SP 800-63B, ENS, INCIBE)

  • Longitud por encima de complejidad: 12+ caracteres, frases.
  • Comprobar contra listas de contraseñas filtradas.
  • Caducidad solo si hay sospecha de compromiso, no cada 90 días por sistema.
  • Bloqueo por intentos, pero con desbloqueo automático para no facilitar denegación de servicio.
  • MFA siempre que se pueda.

Lo que verás en empresas (y en el examen)

  • 8–10 caracteres con complejidad 3 de 4.
  • Caducidad 90 días, historial 5.
  • Bloqueo tras 5 intentos, 15–30 minutos.

Son requisitos de normativas antiguas que siguen en muchos pliegos. Debes saber configurarlos y saber argumentar por qué la longitud importa más.

🤔 ¿Por qué obligar a cambiar la contraseña cada 30 días puede ser contraproducente? (clic)
Porque la gente acaba con patrones predecibles (Enero2026!, Febrero2026!) o las apunta. Mejor larga, única y cambiada cuando haya motivo.
9 · RESUMEN

Para llevarse a casa

  1. Calidad (qué contraseña vale), vida (cuánto dura), bloqueo (cuántos intentos), cuenta (hasta cuándo existe).
  2. Linux: chage por cuenta, login.defs para las nuevas, pwquality para calidad, faillock para bloqueo.
  3. Windows: secpol.msc (o net accounts) para el equipo; net user para cada cuenta.
  4. Las pruebas se hacen como el usuario, no como root/Administrador.
  5. Mantén una sesión de administrador abierta cuando toques PAM.
