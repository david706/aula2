Odoo con Docker y arranque automático

Guía paso a paso · SGE · 2.º DAM · Ubuntu Server 24.04 LTS

Objetivo

Resultado: una instalación formada por Odoo 19 y PostgreSQL 15. Los datos quedan guardados en volúmenes y los contenedores vuelven a arrancar si fallan o si se reinicia la máquina virtual.
ServicioFunciónAcceso
OdooAplicación ERPhttp://IP-DE-LA-MV:8069
PostgreSQLBase de datos de OdooSolo desde la red interna de Docker
Importante: Odoo utiliza PostgreSQL, no MariaDB. En PostgreSQL se mantiene POSTGRES_DB: postgres; la base empresa_dam2 se creará después desde la página de Odoo.

Sistema operativo del laboratorio

Decisión para el curso: utilizaremos Ubuntu Server 24.04 LTS tanto para Docker como para la instalación nativa de Odoo 19. Así todos los equipos parten de la misma plantilla y evitamos diferencias de versiones.
PrácticaSistemaInstalación
Primera instalaciónUbuntu Server 24.04 LTSDocker + Compose + Odoo 19 + PostgreSQL
Instalación comparativaUbuntu Server 24.04 LTSOdoo 19 nativo mediante el paquete oficial .deb
No utilizar Ubuntu 26.04 en estas prácticas: el paquete odoo_19.0.latest_all.deb está preparado para Ubuntu 24.04 noble. No se deben mezclar repositorios ni forzar dependencias de versiones diferentes.
¿Por qué no utilizamos la versión más reciente de Ubuntu?

Ubuntu 24.04 incluye Python 3.12 y es la versión para la que se preparó el paquete de Odoo 19. Ubuntu 26.04 incorpora una generación posterior de Python y cambios en varios paquetes del sistema.

Al intentar instalar el paquete de Odoo 19 en Ubuntu 26.04 pueden aparecer dependencias incompatibles o con nombres diferentes, como python3-freezegun y python3-renderpm. Resolverlo exigiría instalar Odoo desde el código fuente, crear un entorno virtual y adaptar dependencias.

Para aprender Docker, Compose, PostgreSQL, Odoo y Python interesa disponer primero de un entorno estable y repetible. Por eso utilizamos Ubuntu Server 24.04 LTS en todas las máquinas del laboratorio.

¿Por qué utilizamos Odoo 19 y no Odoo 20?

Odoo 20 es una versión estable, no una versión experimental. Sin embargo, acaba de publicarse y todavía tiene menos recorrido en instalaciones educativas y de producción.

Para este curso elegimos Odoo 19 porque:

  • ha recibido más correcciones y lleva más tiempo utilizándose;
  • dispone de más documentación, ejemplos y soluciones conocidas;
  • los módulos comunitarios y complementos tienen mayor disponibilidad;
  • su instalación está comprobada con Ubuntu Server 24.04 LTS y Python 3.12;
  • permite preparar actividades que no cambien durante el curso;
  • facilita distinguir un error del alumnado de una incidencia reciente de la plataforma.

La decisión no significa que Odoo 20 sea malo o inestable. Se prioriza Odoo 19 porque necesitamos un entorno maduro, documentado, reproducible y común para todo el grupo. Odoo 20 puede reservarse para una demostración final o una actividad comparativa.

1Instalar Docker

sudo apt update
sudo apt install docker.io docker-compose-v2 -y
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"
newgrp docker

Comprobamos la instalación:

docker --version
docker compose version
systemctl is-enabled docker
systemctl is-active docker

Los dos últimos comandos deben responder enabled y active.

2Preparar el proyecto

mkdir -p ~/odoo/addons
cd ~/odoo
nano compose.yaml

Pegamos este contenido completo:

services:

  db:
    image: postgres:15
    container_name: odoo-db
    restart: unless-stopped
    environment:
      POSTGRES_DB: postgres
      POSTGRES_USER: odoo
      POSTGRES_PASSWORD: odoo
    volumes:
      - datos-postgres:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U odoo -d postgres"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s

  odoo:
    image: odoo:19.0
    container_name: odoo-web
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
    ports:
      - "8069:8069"
    environment:
      HOST: db
      USER: odoo
      PASSWORD: odoo
    volumes:
      - datos-odoo:/var/lib/odoo
      - ./addons:/mnt/extra-addons

volumes:
  datos-postgres:
  datos-odoo:

Guardamos en Nano con Ctrl+O, Enter y Ctrl+X.

¿Qué hace restart: unless-stopped? Docker intenta volver a levantar el contenedor si se cae y también después de reiniciar Ubuntu. No lo arrancará automáticamente si el administrador lo detuvo expresamente.

3Validar y arrancar

cd ~/odoo
docker compose config
docker compose pull
docker compose up -d

La primera descarga puede tardar varios minutos. Comprobamos el estado:

docker compose ps
docker compose logs --tail=50 odoo

Los contenedores esperados son odoo-db y odoo-web. PostgreSQL debe aparecer como healthy.

4Crear la base de datos de Odoo

  1. Averigua la IP con hostname -I.
  2. Abre http://IP-DE-LA-MV:8069 en el navegador.
  3. Indica Master Password: admin, salvo que se haya cambiado.
  4. Escribe como nombre de base de datos empresa_dam2.
  5. Completa correo, contraseña, idioma y país.
  6. Pulsa Create database y espera sin actualizar la página.
No crees empresa_dam2 mediante POSTGRES_DB. Si PostgreSQL crea una base vacía con ese nombre, Odoo puede intentar usarla sin que existan sus tablas y mostrar el error ir_module_module does not exist.

5Probar el rearranque automático

Primero comprobamos que los servicios están funcionando:

cd ~/odoo
docker compose ps

Reiniciamos la máquina virtual:

sudo reboot

Cuando Ubuntu vuelva a arrancar, entramos de nuevo y comprobamos:

cd ~/odoo
docker compose ps

Odoo y PostgreSQL deben aparecer otra vez como iniciados sin ejecutar docker compose up -d.

Solución de errores

Odoo no abre en el navegador
cd ~/odoo
docker compose ps
docker compose logs --tail=80 odoo

Comprueba también la IP de la MV, el modo de red de VirtualBox y que el puerto 8069 no esté bloqueado.

Error: ir_module_module does not exist

La base existe pero no está inicializada. Si es una instalación nueva y no contiene datos, detén Odoo, elimina únicamente esa base defectuosa y vuelve a crearla desde el navegador.

docker compose stop odoo
docker exec -it odoo-db psql -U odoo -d postgres \
  -c "DROP DATABASE empresa_dam2 WITH (FORCE);"
docker compose start odoo
Permission denied al utilizar Docker

Cierra la sesión de Ubuntu y vuelve a entrar. También puedes ejecutar temporalmente newgrp docker.

Docker Compose no encuentra el archivo

Entra en la carpeta del proyecto antes de ejecutar los comandos:

cd ~/odoo
ls
docker compose ps

Lista final de comprobación

  • Docker está enabled y active.
  • El archivo se llama exactamente compose.yaml.
  • PostgreSQL utiliza POSTGRES_DB: postgres.
  • Los dos servicios tienen restart: unless-stopped.
  • odoo-db aparece como healthy.
  • Odoo responde en el puerto 8069.
  • Después de reiniciar la MV, ambos contenedores vuelven a arrancar.
