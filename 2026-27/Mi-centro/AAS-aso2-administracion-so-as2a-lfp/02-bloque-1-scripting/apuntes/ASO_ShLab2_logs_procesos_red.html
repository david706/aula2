1. Logs: el diario del sistema


Un log (registro) es un fichero donde el sistema y los servicios van apuntando lo que les pasa: arranques, usuarios que entran, errores, intentos de ataque… Cuando algo falla, el log es el primer sitio donde mirar. En Linux viven en /var/log.


FicheroQué contiene


/var/log/syslogMensajes generales del sistema y de los servicios (en Debian/Ubuntu con rsyslog; en Ubuntu 24.04 ya no existe por defecto: todo va al journal).


/var/log/auth.logAutenticación: entradas por SSH, sudo, su, contraseñas fallidas. El log de seguridad.


/var/log/kern.logMensajes del núcleo (hardware, discos, USB, red, memoria).


/var/log/apache2/access.log y error.logPeticiones y errores del servidor web. Cada servicio suele tener su carpeta.


/var/log/dpkg.logPaquetes instalados y eliminados.


/var/log/journal/El journal de systemd, en formato binario: no se lee con cat, sino con journalctl.


Anatomía de una línea de log


Sep 24 09:18:22 aso sshd[1350]: Failed password for root from 203.0.113.5 port 51300 ssh2
│              │   │    │       └ mensaje
│              │   │    └ PID del proceso
│              │   └ programa (identificador)
│              └ equipo
└ fecha y hora


Las líneas de texto se trabajan con las herramientas que ya conoces: grep para filtrar, awk/cut para sacar campos, sort | uniq -c para contar repeticiones, tail para ver el final.


tail -n 20 /var/log/auth.log              # las 20 últimas líneas
tail -f /var/log/syslog                   # seguir el fichero "en directo" (Ctrl+C para salir)
grep "Failed password" /var/log/auth.log  # solo las contraseñas fallidas
grep -c "Failed password" /var/log/auth.log            # cuántas
grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn
                                          # IPs atacantes ordenadas por nº de intentos
grep -i error /var/log/syslog | tail -n 5
sudo grep -r "sda" /var/log/              # buscar en todos los logs


Permisos. Muchos logs solo los puede leer root o el grupo adm. Si cat dice Permiso denegado, usa sudo. En el simulador el usuario alumno ya está en adm.


Rotación. Para que no crezcan sin límite, logrotate los comprime y renombra cada cierto tiempo: auth.log, auth.log.1, auth.log.2.gz… Los comprimidos se leen con zcat o zgrep.



2. journalctl: el journal de systemd


Desde que los sistemas usan systemd, todos los mensajes (kernel, servicios, autenticación…) se guardan además en un registro único y estructurado llamado journal. Se consulta con journalctl, que permite filtrar sin necesidad de grep: por servicio, por gravedad, por fecha, por arranque…


OrdenQué hace


journalctlTodo el journal, de más antiguo a más nuevo (dentro de un paginador: q para salir).


journalctl -n 20 · -rLas 20 últimas líneas · en orden inverso (las nuevas primero).


journalctl -fSeguir en tiempo real (como tail -f). Ctrl+C para salir.


journalctl -u sshSolo los mensajes de la unidad (servicio) ssh.service. Combínalo con -n, -f, -p…


journalctl -p errSolo prioridad err o más grave. También -p warning, -p 3, o un rango -p warning..crit.


journalctl -kSolo mensajes del kernel (equivale a dmesg).


journalctl -b · -b -1 · --list-bootsEste arranque · el anterior · lista de arranques registrados.


journalctl --since today · --since "09:10" --until "09:20" · --since "1 hour ago"Filtrar por fecha y hora.


journalctl -g "Failed"Filtrar por expresión regular (como grep).


journalctl -xeExplicaciones extra (-x) y saltar al final (-e). Es lo que te sugiere systemctl cuando un servicio falla.


journalctl -o catSolo el texto del mensaje (sin fecha ni programa). Útil en scripts.


journalctl --no-pagerSin paginador: imprescindible dentro de un script o con una tubería.


journalctl --disk-usage · sudo journalctl --vacuum-time=7dEspacio que ocupa · borrar lo anterior a 7 días.


journalctl _PID=1350 · _COMM=sshdFiltrar por campos del journal (PID, programa…).


Las 8 prioridades (syslog)


NºNombreSignificado


0emergEl sistema no se puede usar.


1alertHay que actuar ya.


2critCondición crítica (disco, hardware).


3errError: algo ha fallado (un servicio no arranca, permiso denegado…).


4warningAviso: todavía funciona, pero ojo.


5noticeNormal pero significativo (un sudo, un servicio que termina).


6infoInformación normal (servicio iniciado, usuario conectado).


7debugDetalle para depurar.


-p err significa "err o peor": muestra 0, 1, 2 y 3. Por eso -p warning enseña más líneas que -p err.


journalctl -p err --no-pager                 # los errores de este arranque
journalctl -u cups -n 5 --no-pager           # ¿por qué no arranca la impresión?
journalctl -u ssh --since "09:00" -g Failed  # ataques por SSH desde las 9
journalctl -k -p warning                     # avisos del kernel
journalctl -p err --no-pager | wc -l         # contar errores (en un script)


Nombre de la unidad. En Ubuntu el servidor SSH es ssh.service (no sshd), aunque el programa se llame sshd. Si -u no devuelve nada, comprueba el nombre con systemctl list-units --type=service.


¿journal o /var/log? Son dos vistas de lo mismo. El journal es más cómodo para filtrar; los ficheros de texto son más fáciles de copiar, enviar o procesar con grep/awk. Un administrador usa los dos. Para que el journal sobreviva a los reinicios debe existir /var/log/journal/ (o Storage=persistent en /etc/systemd/journald.conf).



3. Procesos: buscar, vigilar y matar


Un proceso es un programa en ejecución. Cada uno tiene un PID (número único), un PPID (el PID de su padre), un usuario propietario, un estado y un consumo de CPU y memoria. El primer proceso es systemd (PID 1) y de él descienden todos los demás. Tu script también es un proceso: su PID está en $$.


OrdenQué hace


ps auxTodos los procesos, estilo BSD: USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND.


ps -efTodos los procesos, estilo System V: UID PID PPID C STIME TTY TIME CMD.


ps -eo pid,ppid,user,%cpu,%mem,comm --sort=-%cpuElige tú las columnas y el orden (- = descendente). comm es el nombre corto; args la orden completa.


ps -u alumno · ps -p 950 · ps -C apache2Los de un usuario · uno concreto por PID · por nombre.


pgrep apache2 · pgrep -x bash · pgrep -l -u alumno · pgrep -c sshd · pgrep -f copiaBusca por nombre y devuelve los PID · nombre exacto · con nombre, de un usuario · cuenta · busca en la orden completa.


top · htop · top -bn1 | head -n 15Monitor en vivo (q sale, k mata, M/P ordena por memoria/CPU) · una captura para scripts.


kill PID · kill -9 PID · kill -15 PIDEnvía una señal: por defecto TERM (15, "termina por favor"); KILL (9, "muere ya", sin opción a limpiar). Prueba primero sin -9.


pkill bucle.sh · killall apache2 · pkill -u pepeMatar por nombre · todos los de un usuario.


uptime · free -h · df -h · nprocCarga media y tiempo encendido · memoria · discos · nº de CPU.


kill -l · kill -0 PIDLista de señales · comprobar si un PID existe sin matarlo.


Columna STAT


R ejecutándose · S durmiendo (espera algo: lo normal) · D espera de disco (no se puede matar) · T parado (Ctrl+Z) · Z zombi (ha terminado pero el padre no lo ha recogido). Sufijos: s líder de sesión, l con hilos, + en primer plano.


ps aux | grep apache2            # ¡también aparece el propio "grep apache2"!
ps aux | grep "[a]pache2"        # truco: el patrón [a]pache2 no se encuentra a sí mismo
pgrep -l apache2                 # lo correcto: solo los PID (y el nombre con -l)
ps -eo pid,%cpu,comm --sort=-%cpu | head -n 3   # los 3 que más CPU consumen
pid=$(pgrep -x bucle.sh); kill "$pid"; echo "Terminado $pid"
sleep 2; kill -0 "$pid" 2>/dev/null && kill -9 "$pid"   # si sigue vivo, a la fuerza


Permisos. Solo puedes matar tus procesos. Para los de otros usuarios o de root hace falta sudo (Operación no permitida). Y nunca mates al azar procesos del sistema: un kill -9 1 ni siquiera funciona, pero matar sshd en un servidor remoto te deja fuera.



4. Servicios: systemctl


Un servicio (o demonio) es un proceso que arranca con el sistema y se queda en segundo plano atendiendo peticiones: ssh, apache2, cron, mysql, cups… systemd los gestiona como unidades (nombre.service) y systemctl es la orden para hablar con él. Procesos, servicios y logs van juntos: si un servicio no responde, mira si su proceso existe (pgrep), su estado (systemctl status) y su journal (journalctl -u).


OrdenQué hace


systemctl status sshEstado completo: activo o no, PID principal, memoria y las últimas líneas de su journal. Código 0 si está activo, 3 si no, 4 si no existe.


systemctl is-active ssh · is-enabled ssh · is-failed cupsRespuestas de una palabra (active, failed, inactive / enabled) pensadas para scripts; con --quiet solo el código de salida.


sudo systemctl start|stop|restart|reload sshArrancar, parar, reiniciar, recargar la configuración. Necesita root.


sudo systemctl enable|disable sshQue arranque (o no) automáticamente con el sistema. enable no lo arranca ahora: para ambas cosas, enable --now.


systemctl list-units --type=service · --failed · list-unit-filesServicios cargados · los que han fallado · todos los instalados y si están habilitados.


systemd-analyze · systemd-analyze blameCuánto tardó el arranque · qué servicio tardó más.


service ssh statusForma antigua (SysV); hoy redirige a systemctl.


if systemctl is-active --quiet apache2; then
    echo "Web OK"
else
    echo "Web caida, reiniciando..."
    sudo systemctl restart apache2
    journalctl -u apache2 -n 5 --no-pager
fi



5. DNS y nslookup


Los equipos se comunican por direcciones IP, pero las personas usamos nombres (www.example.com). El DNS es la guía telefónica que traduce unos en otros. Cuando escribes un nombre, el sistema lo resuelve en este orden (fichero /etc/nsswitch.conf):


  • /etc/hosts: tabla local, manual. Sirve para nombres de tu red o para pruebas: 192.168.1.10  servidor.aula.local servidor.
    • 

  • Los servidores DNS configurados en /etc/resolv.conf (nameserver 192.168.1.1). En Ubuntu moderno verás nameserver 127.0.0.53: es systemd-resolved, un intermediario local que a su vez pregunta a los DNS reales (míralos con resolvectl status). search aula.local es el dominio que se añade a los nombres cortos: servidor → servidor.aula.local.


Tipos de registro que preguntarás


RegistroSignificado


A / AAAANombre → IPv4 / IPv6. El más habitual.


PTRInverso: IP → nombre (nslookup 8.8.8.8).


MXServidores de correo de un dominio (nslookup -type=mx google.com).


CNAME · NS · TXTAlias · servidores de nombres del dominio · texto (SPF, verificaciones).


Leer la salida de nslookup


$ nslookup www.example.com
Server:         127.0.0.53          ← a quién he preguntado (el DNS que uso)
Address:        127.0.0.53#53       ← su IP y puerto (53)

Non-authoritative answer:           ← viene de una caché, no del servidor dueño del dominio
Name:   www.example.com
Address: 93.184.216.34              ← LA RESPUESTA

$ nslookup noexiste.example.com
Server:         127.0.0.53
Address:        127.0.0.53#53

** server can't find noexiste.example.com: NXDOMAIN   ← el nombre no existe (código de salida 1)


MensajeQué significaDónde está el problema


NXDOMAINEl DNS responde: ese nombre no existe.Has escrito mal el nombre, o el dominio no está dado de alta.


SERVFAILEl DNS no ha podido resolverlo.El servidor DNS tiene un problema o no tiene salida a Internet.


;; connection timed out; no servers could be reachedNadie contesta en el puerto 53.IP de DNS equivocada en resolv.conf, red caída o cortafuegos.


nslookup www.example.com 8.8.8.8     # preguntar a otro servidor (el de Google) para descartar el tuyo
nslookup 192.168.1.10                # resolución inversa
nslookup -type=mx google.com         # registros de correo
dig +short www.example.com           # solo la IP: perfecto para scripts
dig www.example.com                  # respuesta detallada, con tiempos y flags
host www.example.com                 # "www.example.com has address 93.184.216.34"
getent hosts servidor                # resuelve como lo haría cualquier programa (mira /etc/hosts también)
cat /etc/hosts /etc/resolv.conf


Error típico en scripts. nslookup nombre | grep Address | tail -1 parece que saca la IP… pero si el nombre no existe te quedas con 127.0.0.53#53, la dirección del servidor DNS. Comprueba siempre el código de salida ($?) o usa dig +short y mira si la variable está vacía.


nslookup interactivo. Si lo ejecutas sin argumentos entras en su propio prompt >: server 8.8.8.8, set type=mx, google.com, exit. Es útil a mano; en scripts usa siempre la forma de una línea.



6. Redes: ver y comprobar la configuración


Para que un equipo esté en red necesita cuatro datos: dirección IP con su máscara (quién está en mi red), puerta de enlace (el router por el que salgo), y DNS. Pueden venir por DHCP (automáticos) o estar fijos en la configuración (/etc/netplan/*.yaml en Ubuntu Server, NetworkManager en escritorio).


OrdenQué hace


ip a (ip addr) · ip -4 a · ip -br aInterfaces y direcciones · solo IPv4 · resumen en una línea por interfaz. lo es la interfaz interna (127.0.0.1); enp0s3, eth0, wlan0… las reales. Busca inet 192.168.1.50/24 y state UP.


ip r (ip route)Tabla de rutas. La línea default via 192.168.1.1 es la puerta de enlace.


ip link · ip neighEstado físico de las interfaces (UP/DOWN, MAC) · tabla ARP (IP ↔ MAC de los vecinos).


hostname -I · hostname -fMis IP · mi nombre completo.


ping -c 4 IP¿Hay respuesta? Siempre con -c: sin él no termina nunca. Código 0 si respondió, 1 si no, 2 si no resuelve el nombre.


traceroute IPPor qué routers pasa el tráfico. Útil para ver dónde se corta.


ss -tuln (antes netstat -tuln)Puertos abiertos: tcp, udp, en escucha, numéricos. Con -p (y sudo) el proceso dueño. 22 ssh, 80 http, 443 https, 53 dns, 3306 mysql.


cat /etc/resolv.conf · resolvectl statusQué DNS uso.


ifconfig, route -n, arp -nÓrdenes antiguas (paquete net-tools); aún las verás en manuales. Equivalen a ip a, ip r, ip n.


nmcli device status · nmcli con showNetworkManager: dispositivos y conexiones.


curl -I http://servidor · wget URLProbar un servidor web desde la terminal.


ip -4 addr show enp0s3 | grep inet | awk '{print $2}' | cut -d/ -f1   # mi IP: 192.168.1.50
hostname -I | awk '{print $1}'                                      # mi IP, forma corta
ip route | grep default | awk '{print $3}'                           # puerta de enlace
ping -c 1 -W 1 192.168.1.1 >/dev/null 2>&1 && echo "Router OK" || echo "Router KO"
ss -tuln | grep ":22 "                                               # ¿escucha el SSH?


Diagnóstico de red en 5 pings (de dentro hacia fuera).

1. ping -c1 127.0.0.1 → ¿funciona la pila TCP/IP? (si falla, problema del sistema)

2. ping -c1 192.168.1.50 (mi IP) → ¿está bien la tarjeta y la configuración?

3. ping -c1 192.168.1.1 (puerta de enlace) → ¿llego al router? (si falla: cable, wifi, IP/máscara mal)

4. ping -c1 8.8.8.8 → ¿tengo salida a Internet? (si falla: el router o el proveedor)

5. ping -c1 www.google.com → ¿funciona el DNS? (si el 4 va y este no: problema de DNS, mira /etc/resolv.conf)



7. Arranque: BIOS/UEFI, NTLDR, BOOTMGR y GRUB


Al encender el equipo ocurre siempre la misma cadena, y saber en qué eslabón falla te dice qué arreglar:


Firmware (BIOS o UEFI) → Gestor de arranque (bootloader) → Núcleo (kernel) → Primer proceso (init / systemd) → servicios → pantalla de login


SistemaGestor de arranqueFicheros de configuraciónHerramientas de reparación


Windows NT/2000/XP/2003NTLDR (NT Loader) + NTDETECT.COMboot.ini (menú y tiempo de espera)Consola de recuperación: fixmbr, fixboot, bootcfg /rebuild


Windows Vista / 7 / 8 / 10 / 11BOOTMGR (Windows Boot Manager, bootmgfw.efi en UEFI)BCD (Boot Configuration Data), una base de datos binariabcdedit, bootrec /fixmbr /fixboot /rebuildbcd, bcdboot, msconfig (pestaña Arranque)


LinuxGRUB 2 (GRand Unified Bootloader)/etc/default/grub (lo que editas) → update-grub genera /boot/grub/grub.cfg (lo que lee GRUB; no se toca a mano). Scripts en /etc/grub.d/.sudo update-grub, sudo grub-install /dev/sda, un Live USB con Boot-Repair, el modo recovery del menú


El famoso "NTLDR is missing"


Aparecía en Windows XP cuando el sector de arranque apuntaba a una partición sin NTLDR (típico al dejar un disquete o USB metido, al clonar mal un disco o al borrar los ficheros ocultos de C:\). Se arreglaba copiando ntldr y ntdetect.com desde el CD y ejecutando fixboot. Su equivalente moderno es "BOOTMGR is missing" o el error 0xc000000f (BCD dañado), que se repara con bootrec /rebuildbcd desde el entorno de recuperación. En Linux el equivalente es quedarse en el prompt grub rescue>: GRUB está pero no encuentra su configuración (se reinstala con grub-install y update-grub desde un Live USB).


Arranque dual y las variables de /etc/default/grub


VariableSignificado


GRUB_DEFAULT=0Entrada del menú que arranca si no tocas nada (0 = la primera; también vale saved o el título entre comillas).


GRUB_TIMEOUT=5Segundos de espera en el menú. GRUB_TIMEOUT_STYLE=hidden lo oculta (pulsa Esc o Mayús para verlo).


GRUB_CMDLINE_LINUX_DEFAULT="quiet splash"Parámetros que se pasan al kernel. Quitar quiet splash muestra los mensajes de arranque; añadir nomodeset arregla problemas gráficos; systemd.unit=rescue.target entra en modo rescate.


GRUB_DISABLE_OS_PROBER=falseBuscar otros sistemas (Windows) y añadirlos al menú.


cat /etc/default/grub
grep "^GRUB_TIMEOUT=" /etc/default/grub | cut -d= -f2    # 5
grep menuentry /boot/grub/grub.cfg                        # entradas del menú (¿hay Windows?)
sudo update-grub                                          # regenerar el menú tras editar la configuración
lsblk                                                     # discos y particiones (sda1 EFI, sda2 /)
systemd-analyze blame | head -n 5                         # qué servicios retrasan el arranque
journalctl -b -p err                                      # errores de este arranque
journalctl -b -1 -n 50                                    # ¿qué pasó justo antes del último reinicio?


Orden de instalación en un arranque dual: primero Windows y luego Linux. Windows sobrescribe el gestor de arranque sin preguntar y te deja sin menú; GRUB, en cambio, detecta Windows y lo añade. Si Windows ha pisado GRUB: Live USB → grub-install → update-grub.



8. Método: cómo investigar un problema


    

  1. ¿Qué servicio falla? systemctl --failed, systemctl status nombre.
    2. 

  2. ¿Qué dice su log? journalctl -u nombre -n 30 --no-pager y journalctl -p err -b. Lee de abajo arriba: el último mensaje suele ser la causa.
    3. 

  3. ¿Existe el proceso? ¿Consume algo raro? pgrep -l nombre, top, free -h, df -h (un disco lleno rompe casi todo).
    4. 

  4. ¿Es la red? Los 5 pings del apartado 6 y ss -tuln para ver si el puerto está abierto.
    5. 

  5. ¿Es el DNS? nslookup nombre; si falla, nslookup nombre 8.8.8.8 para saber si el culpable es tu servidor DNS.
    6. 

  6. ¿Es seguridad? /var/log/auth.log, lastb (intentos fallidos de login), last (quién ha entrado).
    7. 

  7. Arregla, reinicia el servicio, vuelve a mirar el log. Y apunta lo que has hecho.

Una tubería (cat f | while read ...) ejecuta el bucle en un subproceso: las variables que cambies dentro se pierden al terminar. Usa done < fichero.
