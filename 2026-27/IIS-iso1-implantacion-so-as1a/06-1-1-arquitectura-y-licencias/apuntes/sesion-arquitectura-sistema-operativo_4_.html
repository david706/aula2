01

Punto de partida: un problema

10 min

Antes de dar ninguna definición, planteamos una secuencia de acciones que todo el mundo reconoce y dejamos que el grupo intente explicarlas.

En tu ordenador, ahora mismo…

  1. Enciendes el ordenador.
  2. Abres Firefox.
  3. Ves un vídeo de YouTube.
  4. Descargas un PDF.
  5. Lo guardas en el SSD.
  6. Conectas unos auriculares USB.
  • ¿Firefox controla directamente la CPU?
  • ¿YouTube decide dónde colocar los datos en la RAM?
  • ¿El programa sabe qué modelo exacto de SSD tienes?
  • ¿Cada aplicación debe conocer cómo funciona cada tarjeta de sonido?

Dejad que el grupo responda y discuta antes de continuar. La conclusión a la que queremos llegar entre todos: ninguna aplicación toca el hardware directamente — algo se encarga de intermediar. Ese "algo" es el sistema operativo.

02

El sistema informático

15 min

Un sistema informático está formado por tres grandes componentes.

Hardware

El soporte físico: CPU, RAM, almacenamiento, dispositivos de E/S, interfaces de red…

No "sabe" que queremos abrir Firefox.

Software

La parte lógica: sistema operativo, aplicaciones, utilidades, controladores, servicios.

Da instrucciones al hardware.

Usuario

Quien utiliza el sistema para conseguir un objetivo concreto.

El propósito de todo lo demás.

Pregunta trampa: ¿dónde pondrías un driver? No es hardware (es código), pero tampoco es una aplicación de usuario — vive en una zona intermedia que retomamos más adelante, en el apartado de drivers.

03

Entonces, ¿qué hace realmente el SO?

15 min

El sistema operativo administra los recursos del equipo y ofrece una forma organizada de utilizarlos: gestiona usuarios, dispositivos de E/S, procesos, memoria, almacenamiento y comunicaciones, además de seguridad y abstracción.

Gestión del procesador

Firefox, LibreOffice, Spotify, el antivirus y las actualizaciones quieren usar la CPU a la vez. ¿Quién decide cuál se ejecuta primero? El sistema operativo — no hace falta entrar todavía en planificación de procesos, solo introducir la idea de que alguien reparte el turno.

Gestión de memoria

Cuando Firefox necesita memoria, no dice "dame exactamente las celdas físicas 0xA4458–0xB2458": la solicita al SO, que decide dónde colocarla y qué hacer cuando escasea (esto volverá con más detalle cuando veamos monitorización, RAM reservada, caché y paginación).

Gestión de almacenamiento

Al hacer Guardar como → trabajo.pdf, LibreOffice no necesita saber el modelo del SSD, el controlador, los sectores físicos ni los comandos NVMe. El SO ofrece una abstracción sencilla:

C:\Usuarios\Alumno\Documentos\trabajo.pdf /home/alumno/documentos/trabajo.pdf

05

El kernel

10 min

Pensadlo como el controlador de tráfico del sistema: el kernel no hace el trabajo de Firefox ni el de LibreOffice, decide cómo esos programas pueden utilizar los recursos disponibles.

Gestiona, entre otras cosas: procesador, memoria, entrada/salida, procesos y comunicación con el hardware.

  • Si Firefox se bloquea, ¿debería bloquearse necesariamente todo el ordenador?

Esta pregunta es la puerta de entrada a los conceptos de aislamiento y protección entre procesos.

06

Drivers

10 min

Es la parte que más se suele confundir con el propio SO. Un driver traduce las órdenes genéricas del sistema operativo a las instrucciones concretas que entiende un dispositivo — es el "puente" entre el SO y los periféricos.
