01

Consideraciones previas a la instalación

Antes de instalar nada hay que preparar el terreno. Esto implica comprobar los requisitos hardware del equipo, reunir la documentación del proveedor y del propio proceso, y entender cómo arranca el equipo — eso último lo vemos en el apartado 2.

Requisitos hardware

Todo sistema operativo exige un mínimo de CPU, RAM, almacenamiento y «otros» requisitos (gráfica, TPM, arquitectura de 32/64 bits, conexión a Internet…) para funcionar correctamente. Comprobarlos antes de instalar evita sorpresas a mitad de proceso.

RequisitoWindows 11Ubuntu 22.04 LTS
CPU1 GHz, 2 núcleos o más, 64 bits, compatible con la lista de Microsoft2 GHz dual-core (recomendado)
RAM4 GB mínimo4 GB mínimo (2 GB en instalación mínima)
Almacenamiento64 GB mínimo25 GB mínimo
OtrosFirmware UEFI con Secure Boot, TPM 2.0, gráfica compatible DirectX 12/WDDM 2.0Resolución mínima 1024×768; sin TPM obligatorio

Fijaos en la diferencia clave: Windows 11 exige TPM 2.0 y Secure Boot de forma obligatoria — algo que Ubuntu no pide — y es la causa más habitual de que un equipo «compatible» con Windows 10 no pueda actualizarse directamente a Windows 11.

Documentación del proveedor de software

Antes de instalar conviene revisar la documentación oficial del fabricante: notas de la versión, requisitos detallados, compatibilidad de drivers y procedimientos de instalación recomendados. Evita incompatibilidades que solo se descubrirían a mitad de la instalación.

02

La secuencia de arranque

Antes de poder instalar nada, hay que entender qué pasa dentro del equipo entre que pulsas el botón de encendido y aparece el instalador en pantalla. Son tres pasos, siempre en este orden:

Paso 1 · Encendido y POST

Al pulsar el botón de encendido, la fuente de alimentación suministra corriente y el firmware ejecuta el POST (Power-On Self-Test): comprueba que CPU, RAM y el resto de componentes básicos funcionan antes de seguir.

GeneraciónMétodo de aviso de errorEjemplo real
BIOS clásica (años 90–2000s)Pitidos del altavoz interno (speaker)«1 largo + 2 cortos» = error de vídeo
BIOS/UEFI híbrida (2010–2015)Pitidos + mensajes breves en pantalla«Keyboard not detected», «CMOS error»
UEFI moderna (actual)Códigos LED o numéricos en la placa baseCódigo «55» = RAM no instalada
Equipos avanzadosDiagnóstico visual y pantalla de arranque con barras o logsLEDs CPU / DRAM / VGA / BOOT

Paso 2 · Ejecución del firmware (BIOS/UEFI)

El firmware, almacenado en ROM/flash, detecta, inicializa y comprueba el hardware, y permite acceder a la configuración de arranque (boot order) y otros parámetros. Orden de arranque configurable típico: 1) red (PXE), 2) medio extraíble (USB, DVD), 3) disco duro interno.

BIOS (Basic Input/Output System) es el firmware clásico, nacido en 1975; al principio se configuraba con jumpers en la placa, luego con una interfaz de texto. UEFI (Unified Extensible Firmware Interface), de 2007, es su reemplazo moderno: interfaz gráfica, soporte de red, compatibilidad con discos grandes (GPT) y más opciones de personalización. Desde 2010 UEFI va sustituyendo poco a poco a la BIOS clásica.

Para acceder al setup del firmware se pulsa una tecla concreta durante los primeros segundos del arranque: Supr, Esc, F2, F9, F10, F12… depende del fabricante.

Paso 3 · Arranque del sistema

El firmware busca en el dispositivo de arranque el sector de arranque o gestor de arranque. Si lo encuentra, cede el control al sistema operativo:

  • BIOS (clásico): BIOS → MBR → cargador del SO → kernel.
  • UEFI (moderno): UEFI → cargador EFI → kernel.

Si no lo encuentra, pasa al siguiente dispositivo del boot order; si ninguno es válido, muestra el error «No bootable device found».

Para no liarse con los términos

EtapaElemento que intervieneQué haceDónde está
① Firmware (BIOS/UEFI)Orden de arranque (boot order)Decide desde qué dispositivo intentar el inicio (USB, disco, red…)En la configuración del firmware (CMOS/NVRAM)
② Dispositivo seleccionadoSector de arranque (MBR / partición EFI)Contiene el primer código que el firmware ejecuta para arrancarEn el disco o unidad de arranque
③ Sistema operativoCargador de arranque (bootloader)Programa que carga el núcleo (kernel) en memoria y le pasa el controlEn el disco del sistema, tras el sector/partición de arranque
03

Elegir el medio de instalación

Para instalar un sistema operativo por primera vez en un equipo necesitas un medio de instalación distinto del disco duro donde vas a instalar. Puede ser:

  • Un pendrive USB de instalación — el método más habitual en un equipo físico.
  • Una imagen ISO cargada directamente en una máquina virtual (VirtualBox, VMware…) — lo que vosotros hacéis en el aula.

El objetivo siempre es el mismo: arrancar el equipo desde ese medio para cargar un entorno temporal de instalación que te permita copiar y configurar el sistema operativo en el disco duro.

Ojo, no confundir con un USB Live

Un sistema operativo Live se ejecuta directamente desde el pendrive o DVD, sin instalarse en el disco. Sirve para probar, reparar o usar el sistema de forma temporal — no para instalarlo. Ejemplos: Ubuntu Live (probar antes de instalar), Kali Linux (auditoría), Tails OS (anonimato), Clonezilla Live (copias de discos).

04

Descargar la ISO

La imagen ISO contiene todo el instalador del sistema operativo en un único archivo. Debe descargarse siempre desde la fuente oficial del desarrollador.

  1. Elegir el sistema operativo (Windows, Ubuntu, Debian…).
  2. Comprobar la compatibilidad con el hardware del equipo: arquitectura 32/64 bits, RAM, espacio en disco, TPM, etc. (ver tabla del apartado 1).
  3. Descargar la ISO desde la web oficial del proveedor.
  4. (Opcional, pero recomendable) Verificar la integridad de la ISO comparando su código hash (SHA256) con el publicado por el proveedor — así te aseguras de que la descarga no se ha corrompido ni manipulado.
05

Crear el medio de arranque

Con la ISO ya descargada, toca preparar un USB para poder arrancar el equipo físico desde él. Herramientas más habituales:

  • Rufus — Windows, la más usada en clase.
  • Ventoy — multiplataforma, permite llevar varias ISOs en el mismo pendrive.
  • Balena Etcher — Windows, Linux y macOS.
  • Media Creation Tool — oficial de Microsoft, solo Windows.

Proceso general: insertar el pendrive (8 GB o más) → seleccionar la ISO → elegir el modo de arranque (UEFI/BIOS) → iniciar la creación del medio.

¿Qué lleva dentro un pendrive de arranque?

  • Un sector de arranque (boot sector) con el código inicial que la BIOS/UEFI puede ejecutar.
  • Un bootloader (GRUB, ISOLINUX…) de pocos MB.
  • Los archivos del sistema operativo extraídos de la ISO.
  • A veces, un entorno temporal (Windows PE o similar).
  • Un sistema de archivos compatible (normalmente FAT32 o NTFS) para que el firmware pueda leerlo — de hecho el firmware UEFI solo sabe leer particiones FAT32, por eso el formateo por defecto en Rufus suele ser ese.
06

Configurar el arranque (BIOS/UEFI)

Para iniciar la instalación, el equipo debe arrancar desde el dispositivo USB que contiene la imagen. Dos formas de conseguirlo:

  • Entrar en la BIOS/UEFI (setup) y cambiar el orden de arranque (boot order) para que el USB vaya primero.
  • Usar el menú de arranque rápido (boot menu) y seleccionar el USB manualmente para esa única vez, sin tocar la configuración permanente.

Teclas habituales para entrar: F2, F12, Esc, Supr — dependen del fabricante de la placa.

07

Instalar GNU/Linux

De UNIX a GNU/Linux, en cuatro frases: UNIX nació en los 70 como sistema potente pero propietario. En los 80, el proyecto GNU impulsó un sistema libre y abierto compatible con UNIX. En 1991 Linus Torvalds creó el núcleo Linux, que completó ese sistema libre. Al combinar el kernel Linux con las herramientas GNU nació lo que hoy llamamos GNU/Linux — y de ahí surgieron cientos de distribuciones adaptadas a distintos usos.

Familia, distro, sabor, entorno

  • Familia: base común que comparte tecnología y gestor de paquetes. Ej.: Debian, Red Hat, SUSE, Arch.
  • Distribución (distro): versión creada por una comunidad o empresa con un propósito concreto. Ej.: Ubuntu, Fedora, openSUSE, Manjaro.
  • Sabor (flavour): variante oficial de una distro con distinto entorno o enfoque. Ej.: Ubuntu → Kubuntu, Xubuntu, Lubuntu.
  • Entorno de escritorio: interfaz gráfica y estilo visual. Ej.: GNOME, KDE Plasma, XFCE, Cinnamon.

Elementos clave en la instalación

  • Estructura flexible de particiones.
  • Sistema de archivos propio: ext4.
  • Gestor de arranque: GRUB2.
  • Creación del primer usuario, con privilegios sudo.
  • Entorno de escritorio configurable.
  • Repositorios de software y controladores libres.

Particionado del disco

👉 El instalador suele proponer una estructura de particionado automática. No hace falta crearla a mano, pero sí conocer su propósito:

ParticiónFunciónRecomendación
/ (raíz)Sistema operativo y aplicacionesObligatoria
/homeArchivos personales de usuarioRecomendable
swapMemoria virtualRecomendable
/boot/efiArranque (UEFI)Solo si el sistema usa UEFI

Sistema de archivos y el estándar FHS

Linux usa ext4 (no NTFS). Las aplicaciones se instalan automáticamente en carpetas del sistema dentro de /: /usr/bin (ejecutables), /usr/lib (librerías), /opt (software externo); los ajustes personales de cada app van en /home/usuario.

Todo sigue una misma estructura, consistente y predecible, respetada por cualquier distro: el FHS (Filesystem Hierarchy Standard). Gracias a él, un paquete se puede instalar en Ubuntu, Debian o Fedora sin adaptaciones — es el mismo papel que en Windows cumplen rutas fijas como C:\Windows o C:\Program Files.

Permisos y rol del usuario

En Linux hay dos niveles: usuario normal (tareas diarias) y administrador / root (tareas del sistema). Ubuntu no trabaja con la cuenta root directamente: usa sudo cuando hace falta, lo que da un control temporal de administrador con trazabilidad de quién lo usó.

08

Instalación desatendida

Una instalación desatendida es la que se realiza sin intervención manual del usuario. En lugar de responder a cada pantalla del instalador (idioma, zona horaria, tipo de instalación, particiones, usuario, contraseña…), todas esas opciones se definen de antemano en un archivo de respuesta.

  • Ahorra tiempo en instalaciones repetitivas (un aula, una empresa).
  • Permite aplicar una configuración idéntica en varios equipos.
  • Reduce errores humanos al automatizar la selección de opciones.
  • Facilita la reinstalación o el despliegue masivo de sistemas.

Para automatizarla hace falta: la imagen ISO del sistema, y un archivo de respuesta con las opciones predefinidas (idioma, zona horaria, usuario, red…). El instalador lee esos datos y hace todo el proceso sin intervención manual.

No es lo mismo que clonar una imagen

Windows XML

La configuración se define en un archivo de respuesta XML que debe corresponder exactamente a la versión de Windows a instalar. Requiere el Windows ADK, que incluye Windows SIM (System Image Manager) para crearlo.

Puede incluir: clave de licencia, nombre de usuario y organización, idioma, zona horaria, configuración de red, componentes opcionales.

GNU/Linux según familia

Se usa una imagen ISO modificada o una instalación por red (PXE). La configuración previa se guarda en un archivo de respuesta que define idioma, zona horaria y teclado, usuarios y contraseñas, particionado, red/hostname/gestor de arranque y paquetes a instalar.

No hay un único sistema: cada familia tiene su propio método y formato.

09

Después de instalar: actualizaciones y drivers

Todo sistema debe adaptarse a los cambios y mantenerse actualizado. Una actualización de software modifica partes del sistema para corregir errores o vulnerabilidades, mejorar estabilidad y rendimiento, o aumentar la seguridad. También existen actualizaciones de hardware (sustitución de componentes), tras las cuales puede ser necesario actualizar el software o firmware asociado.

Tipos de software, para tenerlo claro

  • Sistema operativo: conjunto de programas que gestionan el hardware.
  • Firmware: software básico instalado por el fabricante en un dispositivo.
  • Aplicación: programa con interfaz gráfica para una tarea concreta.
  • Programa: conjunto de instrucciones que ejecuta una tarea.
  • Librería: funciones que usan otros programas.
  • Paquete: contenedor de programas, librerías o drivers.
  • Parche: corrección de errores en un software.
  • Driver: instrucciones que permiten al SO comunicarse con un dispositivo.

Windows

El servicio Windows Update mantiene el sistema actualizado; por defecto las actualizaciones se descargan e instalan automáticamente. Tipos: de seguridad, de calidad, de características, de controladores (drivers). Las aplicaciones instaladas no se actualizan por Windows Update, sino por sus propios sistemas o desde la Microsoft Store.

GNU/Linux

Las actualizaciones se gestionan con el gestor de paquetes de cada distro, normalmente desde repositorios oficiales: apt update && apt upgrade (Debian/Ubuntu), dnf update (Red Hat/Fedora), zypper update (openSUSE). A diferencia de Windows, sistema y aplicaciones instaladas por el gestor se actualizan juntos desde una sola herramienta.

10

Documentar y formar

Elaborar manuales y guías de uso es parte fundamental del trabajo del administrador de sistemas. La documentación debe hacerse durante el proceso de instalación, para recoger todos los pasos y configuraciones realizadas — no de memoria al final. También hay que planificar la formación de los usuarios: copias de seguridad y actualizaciones previas a la instalación, uso de los dispositivos y aplicaciones que acompañan al sistema. Además, la prevención de riesgos laborales debe contemplar formación sobre uso seguro de equipos, ergonomía y condiciones del puesto de trabajo.

Mala prácticaBuena práctica
Notas personales en una libreta o archivos sueltosDocumentar el proceso en un formato digital estructurado (informe o wiki)
Sin capturas, versiones del sistema ni fechasCapturas, comandos usados, versiones y fechas
Documento no compartido con el resto del equipoGuardado en una ubicación compartida accesible para todos
Sin control de versiones ni trazabilidadSe actualiza cada vez que se modifica el procedimiento
Cada técnico repite el proceso «a su manera»Todos siguen las mismas instrucciones y mantienen coherencia

Ejercicios

1 · Diagnóstico POST

Mira tu propio equipo (o el de la máquina física del aula, no la VM): ¿qué método de aviso usa su firmware si falla el POST — pitidos, mensajes en pantalla, LEDs, código numérico? Búscalo en la documentación de la placa base si no lo sabes de memoria.

Pista
Mira el manual de la placa base (modelo exacto) o el logo que aparece al arrancar: casi siempre indica si es BIOS clásica, híbrida o UEFI moderna.
Cómo contrastarlo

No hay una única respuesta correcta — depende del hardware real de cada uno. Lo importante es que sepáis identificar en qué categoría de la tabla del apartado 2 cae vuestro equipo y por qué.

2 · Elige el método correcto

Para cada situación, decide si conviene una imagen clonada, una instalación desatendida, o una instalación manual normal.

Caso A

20 ordenadores idénticos en un aula, todos con el mismo sistema y programas. Al final del día deben volver a su estado inicial.

Caso B

5 ordenadores nuevos con hardware distinto cada uno, todos deben llevar Windows 11.

Caso C

Una sala de servidores sin lector USB: los equipos deben instalarse por red (PXE) de forma completamente automatizada y repetible.

Solución razonada

Caso A — Imagen clonada. Hardware idéntico y se necesita volver siempre al mismo estado exacto: clonar es más rápido que reinstalar, y no hace falta adaptar nada.

Caso B — Instalación desatendida. Hardware distinto en cada equipo, así que una imagen clonada podría dar problemas de compatibilidad; un archivo de respuesta permite automatizar sin perder flexibilidad.

Caso C — Instalación desatendida por red (PXE + archivo de respuesta). Sin USB no se puede clonar fácilmente ni arrancar desde medio físico; el archivo de respuesta vía red es la solución estándar para este escenario.
